## 1. 需要你拍板的（按是否阻塞下游排序）

### 🔴 阻塞 2.1 骨架（不拍板就没法开工）

**Q-16 前端用 TypeScript 还是 JavaScript**
- 选项：A TS（`types/api.ts` 与契约一一对齐，字段名/可空性错不过编译）· B JS + JSDoc · C TS 但关掉严格模式
- 推荐：**A**
- 影响：`web/` 全部文件后缀、`tsconfig`、`vue-tsc` 步骤、4.1 与 4.2 的产出物形态
- 可逆：低（后期从 JS 迁 TS 是一次全量重写式改造）→ **标为不可逆点③**
- 依据：你的熟练度。如果 JS 更熟，C 比 A 更现实，别为"类型安全"把 4.1 拖成瓶颈。

**Q-17 样式方案：手写 CSS + token / Tailwind / Sass**
- 推荐：手写 CSS + `styles/tokens.css`（已在基线）
- 影响：4.2 UI 还原的全部产出物、新页面书写速度
- 可逆：中（Tailwind 迁移是重写所有 `class`）
- 备注：如果你已在别的课用熟了 Tailwind，告诉我，我改基线而不是你改习惯。

**Q-18 执行环境：JDK + MySQL + Maven 在哪台机器上**
- 实测发现：**本 Agent 运行机 `PATH` 无 `java`/`mvn`/`mysql`**（只有 Node 22.23.3 与 Git 2.56），`C:\Program Files` 下也未发现 JDK/MySQL/Maven 安装。
- 影响：2.1 的验收「干净环境按 README 命令启动前后端 + 脚本能建表」**必须**在有 JDK 与 MySQL 的机器上跑；否则 2.1 会因环境缺失卡住，与代码无关。
- 需要你做的：确认 2.1 指派到的 Computer 是否装有 JDK 17 + MySQL 8.0，或先装。
- 可逆：不适用（环境问题）

### 🟠 阻塞 3.1 后端接口（影响字段与错误码，写代码前需要答案）

**Q-01 `contact` / `publisherName`：必填性、是否脱敏、谁可见**
- 选项：A 都选填、详情原样展示（当前基线）· B `contact` 必填、详情原样 · C `contact` 必填且列表脱敏（`138****0001`）· D 去掉 `publisherName`
- 推荐：**B**（没有联系方式的招领帖实际不可用）+ 列表不返回 contact（基线已这么定）
- 影响：`t_record.contact/publisher_name` 可空性与 CHECK、DTO 校验注解、前端提交页必填标记、详情页展示
- 可逆：**列改可空易（`MODIFY`），改回不可空难（已有 NULL 数据）** → **不可逆点④**
- 隐私提醒：无登录 ⇒ 任何访客都能通过 `/api/records/{id}` 拿到联系方式。这是产品定位问题（"公开启事"）而不是技术问题，答辩时可能被老师问到，建议提前定口径。

**Q-02 无登录 ⇒ 状态流转由"任何访客"触发，是否接受**
- 现状推论：详情页的状态按钮（`PATCH /api/records/{id}/status`）对任何访客可用，任何人可把别人的帖子改成"已领"或"关闭"，系统无法判断其是否为拾主本人。
- 选项：A 接受（课程版，答辩时如实说明这是"无权限体系的代价"）· B 提交时生成一条"改单口令"，PATCH 需带它（弱化版鉴权，约 0.5 天，需要 `t_record` 加一列 `edit_token`）· C 去掉前端的状态按钮，只留展示
- 推荐：**A**，并在 6.1 设计文档的"已知限制"里明写（父任务已把权限体系列为范围外，B 属于悄悄把鉴权做回来，我不主动加）
- 影响：选 B 需要加列（**不可逆点⑤**）+ 契约加一个必填头 + 前端多一步"保存口令"的交互；选 C 只减不改
- 可逆：A→B 需要改表与契约（成本中等）；A→C 纯前端（易）
- 关联：与 Q-01 的隐私问题是同一个根因（无身份体系），建议一次拍板

**Q-03 删除与下架的业务规则**
- 待明确：1) 谁可以删（无登录 ⇒ 事实上任何访客）2) `CLAIMED`/`CLOSED` 是否允许删 3) "删除"是否就是 `CLOSED` 的别名 4) `CLAIMED → PENDING`（撤销认领）允不允许
- 推荐：允许任意状态删除（逻辑删）；不允许 `CLAIMED→PENDING`；`CLOSED` 终态
- 影响：`RecordStatusPolicy` 流转表、错误码 `20002/20003` 的触发条件、`allowedStatuses` 内容、详情页按钮
- 可逆：中（规则改一次，测试用例跟着改）。**但若第 3) 项的答案是"删除就是 CLOSED"，`t_record.deleted_at` 要删列 ⇒ 不可逆点⑥**（语义收窄容易、放开难，且快照的悬空引用会立刻变成可见死链）
- **这条主要属于 1.1 的范围，我在 DDL 与契约里只是预留了承载能力**

**Q-04 标题/描述/地点/联系方式的字数上限**
- 基线默认：title 2–64、description 2–2000、location 1–128、contact 1–64、publisherName 1–32
- 影响：`schema.sql` 的列长度 + CHECK、DTO 校验、前端表单计数器
- 可逆：**DDL 列长度缩窄属不可逆（截断已有数据）** → **不可逆点①的实例**
- 需要谁：1.1 给业务口径，我这边同步三处

**Q-08 `occurredAt` 是否允许晚于当前时间**
- 基线：允许 `now + 5min` 容差（防客户端时钟偏差），不允许未来
- 选项：允许填未来（"我明天要在图书馆丢东西"是荒谬的）/ 完全禁止未来 / 不做限制
- 影响：提交页校验与后端 CHECK 位置（当前放应用层，不放 DB）

**Q-05 列表默认 `status=PENDING`（还是全部）**
- 影响：列表页首屏内容、筛选栏是否要"全部"选项、URL query 默认值
- 可逆：高（前端一处默认值 + 后端一处默认值）

### 🟡 阻塞 3.2 AI 匹配（不影响接口签名，只影响实现选择与阈值）

**父任务待确认 #1 / Q-19 课程版 `/api/match` 取哪种实现**
- 选项：A 本地关键词+相似度（默认，离线可演示、结果确定）· B 外部模型/嵌入服务（"语义"更名副其实，需 Key/配额/网络）· C 两者都实现、演示时切换（基线的装配方式已支持，成本约 0.5 天额外）

- 可逆：高（`findit.match.engine` 一个配置值 + 两个环境变量）

**Q-06 相似度展示口径与阈值**
- 基线：`score ∈ [0,1]`，展示 `相似度 83%`，默认 `minScore=0.3`
- 待你确认：百分比会不会被老师质疑"这个 83% 是怎么算出来的"？备选的更保守口径：只显示"高/中/低相关"三档
- 影响：`MatchItem` 是否保留 `scorePercent`、MatchPanel 的视觉、5.1 评估指标定义
- 可逆：中（**跨实现分数不可比**是这条的真正约束，已在 ADR/§8.4 写明）

**Q-07 匹配返回条数上限**：默认 5、上限 20（基线）。影响：`topN` 校验、MatchPanel 高度

**Q-10 外部引擎失败是否自动降级本地**
- 推荐：**不降级**（503 + 匹配区局部降级 UI），理由见 ADR-009（评估数据不被污染、答辩诚信）

- 可逆：高（一处装配 + 一处注入）

**Q-09 是否需要第四张表 `t_match_candidate`**
- 触发条件：5.1 要用 SQL 聚合统计命中率/分类分布；或外部实现要持久化 embedding
- 当前基线：候选存 `t_match_result.candidates` JSON，评估脚本读 JSON
- 影响：**任务边界明确写了"三张表固定，第四张须先报"** → 这条只能你点头
- 可逆：**不可逆点⑤（一旦建表并有数据，回收要 DROP）**
