# UI 与组件基线（4.2 交付物）

> **一句话**：三个页面现在共用一套 token、一套原始类、一套组件语义；五种状态各有一条确定的视觉规则。本文是视觉与交互的事实源——照着它实现，不需要再回来问颜色、间距或组件用法。
>
> **v2 增补（2026-10-27）**：身份、置信度与通知的界面基线见 §11–§23；v1 的 §1–§10 仍然有效，两者不冲突。v2 稿面在 `docs/ui/v2/`。
>
> **基线**：`feat/4.1-frontend-pages` @ `4f637ea` → 本任务分支 `feat/4.2-ui-baseline`
> **技术栈**：Vue 3.5.44 + Vite 8.3.5 + TypeScript 5.9.3 + vue-router 5.4.0（未新增任何运行时依赖）
> **验证环境**：Windows 11 · Node 22.23.3 · npm 10.9.9 · Edge 155.0.4283.62（Playwright 驱动，headless）

## 0. 结论先行

1. **不引 UI 库、不引 Web 字体、不引图标字体**。全站 CSS 27.4 kB（gzip 6.8 kB），列表页首屏 JS+CSS 48.5 kB（gzip）。理由见 §2.4、§5.3。
2. **颜色只有三组**：中性灰（色相向品牌蓝偏，避免发脏）、品牌蓝、语义色（寻物红 / 招领绿 / 状态三色）。组件里**不允许出现十六进制或颜色函数**。
3. **圆角三档各司其职**：控件与按钮 `6px`、面板与卡片 `10px`、徽标 `pill`。按钮不做全圆——全圆按钮配通用阴影是"AI 味"最重的组合之一。
4. **同类元素只写一次**：`.btn` / `.page-head` / `.panel` / `.control` / `.field` / `.badge` / `.alert` / `.empty` / `.skeleton` / `.score` 十个原始类族落在 `styles/components.css`，三页的筛选区、表单、详情卡、提示条现在共用同一套高度、边框和圆角。
5. **五状态各有确定视觉**：默认、加载（骨架）、空（`EmptyState`）、错误（`ErrorBanner` + 重试）、校验失败（字段红框 + `!` 文案 + 页级可点摘要）。矩阵见 §4。
6. **`/api/match` 结果四条一起构成"可读 + 排序可见"**：名次 `1/2/3…`、相似度进度条、百分比、命中原因文案，外加一条明确排序说明（§4.5）。
7. **320px → 1280px 无横向溢出**（18 张截图逐个断言 `scrollWidth === innerWidth`），CLS 实测 0.000–0.004（阈值 0.1），见 §5。
8. **深色模式本期不做**，但已把接入成本压到"只在 `tokens.css` 追加一段同名覆盖"；这是需要人类拍板的待确认项（§8）。

## 2. 视觉基线

### 2.1 色彩

三组语义，全部集中在 `web/src/styles/tokens.css`。

**中性**（注意：不是纯灰，色相 220° 左右向品牌蓝偏移）

| Token | 值 | 用途 |
|---|---|---|
| `--color-bg` | `#f4f6fb` | 页面底色 |
| `--color-surface` | `#ffffff` | 卡片 / 面板 / 顶栏 |
| `--color-surface-muted` | `#eef1f7` | 禁用态底、标签底、序号底 |
| `--color-surface-sunken` | `#e6eaf3` | 骨架屏底色 |
| `--color-border` | `#e0e5ef` | 面板/卡片描边（装饰性） |
| `--color-border-strong` | `#c6cddc` | ghost 按钮描边 |
| `--color-control-border` | `#8b94a4` | **表单控件专用描边**，白底 3.06:1 |
| `--color-text` | `#1a2033` | 正文 / 标题 |
| `--color-text-muted` | `#5b6478` | 次要信息 |
| `--color-text-subtle` | `#687185` | 12px 辅助信息（时间、编号、页脚） |

**品牌**：`--color-primary #2450d0`、`--color-primary-strong #1a3ca6`（hover/active）、`--color-primary-soft #e7eefc`（选中底）、`--color-primary-softer #f2f6fe`（浅底）、`--color-on-primary #ffffff`。

**语义**：`danger #c2352b`（+ soft `#fdecea`）、`warning #8a5300`（+ `#fdf3e2`）、`success #17784a`（+ `#e6f5ec`）、`info #0b6373`（+ `#e3f2f5`）。

**类型与状态映射**（唯一的映射点在 `RecordTypeTag.vue` / `RecordStatusTag.vue`，别处不许各写一套）

| 语义 | 文字 | 前景 / 底色 |
|---|---|---|
| 寻物 LOST | 寻物 | `--color-type-lost-fg/bg` → danger / danger-soft |
| 招领 FOUND | 招领 | `--color-type-found-fg/bg` → success / success-soft |
| 进行中 PENDING | 进行中 | info / info-soft |
| 已完成 COMPLETED | 已完成 | success / success-soft |
| 已关闭 CLOSED | 已关闭 | text-muted / surface-muted |

**记录状态只有三值**：`PENDING` / `COMPLETED` / `CLOSED`，中文文案固定为「进行中 / 已完成 / 已关闭」。`PENDING` 用「进行中」是为了与 `/my` 页签现有文案一致。**「已完成」不是「已关闭」的别名**：前者是本人确认拿到结果后的收尾，后者是本人主动下架；两态的徽标颜色（success / text-muted）、文案与入口都必须能区分。旧状态枚举与两个旧中文标签在本轮全部清除，`check-copy.ps1` 会做 0 命中检查。

**规则**
- 组件里只写 `var(--…)`；`#fff` 级别的字面量只允许出现在 `tokens.css`。
- 状态永不只用颜色表达：徽标 = 底色 + 文字 + 6px 色点，三通道（§6.3）。
- 新增语义 = 新增 token，不许就地调色。

### 2.2 字号与层级

正文 14px 起（不拿 12px 当正文），四级足够：

| 级 | Token | 值 | 用途 | 行高 |
|---|---|---|---|---|
| 展示 | `--fs-display` | `clamp(22px, 5vw, 30px)` | 页面主标题 `.page-head__title` | 1.25 |
| 标题 | `--fs-2xl` / `--fs-lg` | 24 / 16 | 详情标题 / 卡片标题、面板标题 | 1.25 / 1.4 |
| 正文 | `--fs-md` | 14 | 正文、控件、按钮 | 1.6 |
| 辅助 | `--fs-sm` / `--fs-xs` | 13 / 12 | 说明、元信息、徽标 | 1.4 / 1.25 |

字重只用 400 / 500 / 600 / 700；标题收紧（`letter-spacing: -0.01em`），正文放宽行高。数字一律 `font-variant-numeric: tabular-nums`（分值、时间、页码对齐用）。

### 2.3 间距、栅格、断点

- **间距刻度**：4px 基准，`--sp-1…--sp-8`（4→40），`--sp-9/--sp-10`（48/64）只给大区块。**页内间距只用刻度值**，不写 `13px` 这种。
- **容器**：`--container-max: 1120px`、页面左右 `16px`（≥768 为 `24px`）。
- **阅读宽**：`--content-max: 760px`（详情描述、表单），约 65 字符。
- **断点只有两个**：`768px`（1→2/3 列）、`1120px`（2→3 列）。写在 token 里，`@media` 与 `matchMedia` 共用同一对数值。
- **竖排节奏**：页面 = `page-head` → 主内容 → 次内容，区块间距 `--sp-4/--sp-5`；页面顶部 `--sp-5`（≥768 `--sp-6`）。

**320px 下的实际表现**（已验证）：顶栏只留 `FI` 标；筛选区 2 列 3 行；卡片单列；页码条换行；无横向滚动。

### 2.4 字体

```
--font-sans: system-ui, -apple-system, 'Segoe UI', 'PingFang SC', 'Microsoft YaHei', 'Noto Sans CJK SC', sans-serif
--font-mono: ui-monospace, 'SF Mono', 'Cascadia Mono', Consolas, monospace  /* 仅编号/分值 */
```

**不引 Web 字体的理由（这是决策，不是偷懒）**：中文字体子集化后仍有几百 KB，弱网下会直接顶到 LCP 预算；`font-display: swap` 又必然带来一次字体切换重排（CLS）。系统 UI 栈在 Windows / Android / iOS 上都是本地字体，**0 下载、0 抖动**，代价只是三个平台字形略有差异——对课程项目完全可接受。

### 2.5 圆角、阴影、动效

| 项 | 规则 |
|---|---|
| 圆角 | 控件/按钮 `--radius-sm 6px`；面板/卡片 `--radius-md 10px`；徽标/进度条 `pill`；小方块（名次、logo）`--radius-xs 4px` |
| 阴影 | 只有两级：`--shadow-sm`（卡片静置）、`--shadow-md`（卡片 hover）；`--shadow-lg` 预留给弹层，当前未使用 |
| 描边 | 1px；卡片左侧的类型色条用 `inset box-shadow` 实现（不占内宽、不引起 1px 抖动） |
| 时长 | `--dur-fast 120ms`（颜色/边框）、`--dur-base 180ms`（位移/阴影）、`--dur-slow 260ms` 预留 |
| 缓动 | 进入 `--ease-out`（减速）、退出 `--ease-in`、颜色用 `--ease-standard` |
| 减少动效 | 全局 `@media (prefers-reduced-motion: reduce)` 把动画/过渡压到 0.01ms，并关掉骨架屏 sheen；实测分值条 `transition-duration` = `1e-05s` |

**关于"只动 transform/opacity"这条更严的口径——我做了偏离，并说明原因**：

- **零布局动画**：全站没有一处过渡 `width / height / top / left / margin / padding`。分值的进度条宽度刻意**不加** transition（宽度是布局属性），渲染时就定值。
- **允许的绘制类动画**：`background-color`、`border-color`、`color`、`box-shadow`。它们只触发绘制不触发布局，是 hover / 焦点反馈必须的；如果也禁掉，按钮 hover 会变成瞬间跳变，反而更差。
- 位移类效果一律 `transform`：卡片 hover `translateY(-2px)`、骨架 sheen `translateX`、按钮 spinner `rotate`、跳转链接 `translateY`。

**这条偏离写在这里，是为了让下一个人知道它不是疏忽。** 若答辩口径必须严格到"只有 transform/opacity"，删掉 4 处 `transition` 即可，视觉会变硬。

### 2.6 深色模式：本期不做（待确认项）

- `html { color-scheme: light }` 显式声明只做浅色，防止 Chrome 自动深色把原生控件反相成和页面不搭的样子。
- 接入方式已经想好：在 `tokens.css` 末尾追加 `@media (prefers-color-scheme: dark) { :root { … } }`，**同名覆盖** 30 个左右的颜色变量即可，组件与页面零改动。
- 成本：主要是重新过一遍对比度（暗底上的 `--color-text-muted` 必换）与阴影在暗底失效的问题。**需要人类确认是否列入本阶段范围**（§8）。

### 2.7 图标

不引图标字体、不引图标库。目前只有一处"图标"——品牌方块里的 `FI` 文字与 favicon 的内联 SVG data URI。理由：三个页面没有必须用图标才能表达的语义，用文字比用装饰性图标更省也更快。

## 3. 组件规格

原始类在 `web/src/styles/components.css`；组件在 `web/src/components/`。**组件内只写布局差异，外观回到原始类**。

### 3.1 按钮

`.btn` + 变体 + 尺寸，`<button>` 与 `<a>/<RouterLink>` 通用。

| 变体 | 用处 | 视觉 |
|---|---|---|
| `.btn--primary` | 页面唯一主操作（发布、提交、开始匹配） | 实底 `#2450d0`，白字 |
| `.btn--ghost` | 次操作（返回、取消、状态流转、筛选重置） | 白底 + 1px 描边 |
| `.btn--danger` | 错误态里的重试 | 白底 + 红描边红字 |
| `.btn--subtle` | 低强调（当前未用，留给文本型操作） | 蓝字无底 |
| `.btn--link` | 错误摘要里的"跳到字段" | 下划线文字按钮，`white-space: normal` 可换行 |

尺寸：默认高 40px、`.btn--sm` 32px（触屏下 `@media (pointer: coarse)` 自动升到 40px）、`.btn--lg` 44px。`.btn--block` 满宽。

状态：`:hover` 换底色/描边；`:active` 用 `inset` 内阴影（不做位移，避免点击时抖）；`:disabled` **不用 opacity**（会把文字对比度一起拉低），改用 `surface-muted` 底 + `text-muted` 字（5.24:1）；`[data-loading]` + `.btn__spinner` 给提交中的转圈。

反例：一屏出现两个 `.btn--primary`；用 `opacity: .6` 表示禁用；给按钮加 `translateY` hover。

### 3.2 表单控件与字段

```html
<div class="field">
  <label class="field__label" for="field-title">
    标题 <span class="field__req">*</span>
    <span class="field__counter">0/64</span>
  </label>
  <input id="field-title" class="control" aria-invalid="true" aria-describedby="field-title-error" />
  <ul id="field-title-error" class="field-error"><li>请填写标题</li></ul>
</div>
```

- `.control`：高 40px、1px `--color-control-border`、`6px` 圆角；`:focus-visible` 用 `box-shadow: var(--ring)` 环（不用 `outline`，圆角处不出缺口）；`[aria-invalid="true"]` 边框转红并换红环。
- `select.control` **保留系统原生箭头**：自绘箭头要内联 SVG 硬编码颜色，跨内核/内嵌 WebView 风险大于收益。
- `textarea.control` 最小高 `2×40`，`resize: vertical`（只允许纵向拉，横向拉会撑破布局）。
- `.radio`：`label` 包住 `input`，整块可点，`:has(input:checked)` 变蓝底蓝框；**一组单选必须用 `<fieldset> + <legend>`**，不能拿 `<label for>` 指向一个 `<div>`（那是无效 HTML，读屏也读不出这组单选在问什么）。
- 表单错误的三条硬规则：
  1. 字段级：`aria-invalid="true"` + `aria-describedby` 指向 `#field-{name}-error`；
  2. 每条错误前面有 `!` 圆点（文字符号，不靠颜色）；
  3. 点过提交后还在表单顶部给一条**页级摘要**（`role="alert"`），列出所有问题并可点回字段——长表单滚到一半看不到红字时，这条是救命的。
- 计数器 `.field__counter` 用 `tabular-nums` + `margin-left: auto` 靠右。

### 3.3 标签 / 徽标

`RecordTypeTag` 与 `RecordStatusTag` 都渲染 `.badge.badge--dot.badge--{type|status}`，**共用同一个原始类**，所以三个页面的徽标高度、内距、字距必然一致。

| props | 类型 | 说明 |
|---|---|---|
| `type` | `'LOST' \| 'FOUND'` | 文案 `寻物 / 招领` 的唯一映射点 |
| `status` | `'PENDING' \| 'COMPLETED' \| 'CLOSED'` | 文案 `进行中 / 已完成 / 已关闭` 的唯一映射点 |

三值语义固定：`PENDING` = 正常发布（进行中），`COMPLETED` = 本人手动标记完成（已完成），`CLOSED` = 本人手动关闭（已关闭）。徽标 class 对应 `.badge--pending` / `.badge--completed` / `.badge--closed`；`COMPLETED` 用 success 语义，`CLOSED` 用 text-muted，**不允许**把两者画成同一套颜色。`.badge--completed` 是 v2 新增，本次只在稿面 `mockup.css` 定义，实现时由 E2 补进 `web/src/styles/components.css`（本轮 `web/` 0 行改动）。

高度 22px、内距 8px、12px/500、色点 6px。**三通道表达状态**：颜色 + 文字 + 圆点，色盲与灰度打印都能读。

### 3.4 加载态

`LoadingBlock.vue`

| props | 默认 | 说明 |
|---|---|---|
| `rows` | `3` | 骨架块数量 |
| `variant` | `'list'` | `list`（卡片网格，跟随 1/2/3 列）/ `detail`（单块）/ `inline`（区内两三行） |
| `label` | `'正在加载'` | 只给读屏（`.sr-only`），视觉上是骨架 |

- 骨架**与真实内容同构**（徽标行 + 标题行 + 两行元信息），高度固定，所以数据回来时不产生 CLS。
- `role="status"` + `aria-busy="true"`；sheen 只动 `transform`，`prefers-reduced-motion` 下不显示。
- 任何页面不许"请求中白屏"——这是 4.1 的验收项，4.2 把它变成唯一实现。

### 3.5 错误态

`ErrorBanner.vue`

| props | 类型 | 说明 |
|---|---|---|
| `error` | `unknown` | 内部调 `describeError()`，组件里不 `switch` 错误码 |
| `title` | `string?` | 默认「加载失败」；提交类传「提交失败」 |
| `retryLabel` | `string?` | 传了就显示重试按钮 |
| `@retry` | `() => void` | 父组件重发**同一个请求** |

- 视觉：`.alert.alert--danger`（红底 + 3px 左边 + 红字），`role="alert"`。
- **每个异步调用都有可行动的失败路径**：列表/详情/匹配/提交都有重试按钮，且重试走的是原来的 `run(...)`，没有新增调用路径。
- 业务空态（`20001` 记录不存在）**不是**错误态，用 `EmptyState` 展示——这两者混淆会让"记录被删了"看起来像"服务挂了"。
- 匹配区的 `30002/30003` 只降级本区（文案「匹配服务暂不可用」），详情主体照常可用。

### 3.6 空态

`EmptyState.vue`

| props | 类型 | 说明 |
|---|---|---|
| `title` | `string` | 一句话结论（`暂无符合条件的启事`） |
| `description` | `string?` | 为什么空 / 当前条件 |
| `actionText` | `string?` | 纯文案建议（动作在别处时用，如"点上方重置筛选"） |
| `actionLabel` | `string?` | 有 `to` 时渲染成按钮 |
| `to` | `RouteLocationRaw?` | 下一步去哪 |

视觉：`.empty`——虚线框、白底、居中、顶部一条 32×3px 的品牌色短横（唯一的装饰，替代"大圆角图标 + 插画"那套 AI 味组合）。空态必须教用户下一步做什么，所以 `to` 优先于 `actionText`。

### 3.7 面板

`.panel`：白底 + 1px `--color-border` + 10px 圆角 + 内距 16（≥768 为 20）。`.panel__head / __title / __desc` 提供标题区。

用它的地方：筛选区、详情正文、提交表单、匹配区。**新增一个"白底带框的块"时必须用它**，不许再写一遍 `border + border-radius + background`——这是三个页面视觉不一致最常见的原因。

### 3.8 相似度分值

`.score` + `data-band`，见 §4.5。

| 元素 | 说明 |
|---|---|
| `.score__bar` | 6px 轨道，`pill` 圆角，底色 `--color-score-track` |
| `.score__fill` | 宽度来自内联 `--score: N%`；颜色来自档位；**无 transition** |
| `.score__value` | `N%`，`tabular-nums`，同档位色 |

分档（**只影响颜色，不参与排序、不改分值**）：`≥70` 高（绿）、`≥40` 中（琥珀）、其余低（灰）。

### 3.9 分页

`PaginationBar.vue`（props `page / pageSize / total`，emit `update:page`）：页码窗口算法保持 4.1 的实现（当前页 ±2 + 首尾 + 省略号），只把外观换成 `.btn.btn--ghost.btn--sm`；当前页用**底色 + 边框 + 字重**三通道，并带 `aria-current="page"` 与 `aria-label="第 N 页"`。

## 5. 性能

### 5.1 方法（可复现）

- `vite build --mode <mock|real>` 的**生产产物**，`vite preview` 本地静态服务，Edge 155 headless，DPR 1，冷缓存（每次 `newContext`）。
- 用 `addInitScript` 装 `PerformanceObserver` 采集 `largest-contentful-paint` / `layout-shift`（忽略 `hadRecentInput`）/ `paint`，`navigation` 取 TTFB。
- 每张截图同时断言 `document.documentElement.scrollWidth <= window.innerWidth`（横向溢出）与收集 `console.error` / `pageerror`。
- **限制**：localhost，无真实网络延迟与带宽限制，单次采样不是多轮中位数。这些数字只能说明"渲染链路没有额外阻塞、没有布局抖动"，**不能**当作弱网下的 LCP。

### 5.4 一个具体的 CLS 案例（值得写下来）

第一轮实测里 320px 的 CLS 是 **0.069**，用 `layout-shift` 的 `sources` 定位到**页脚**：内容短的时候 flex 把页脚顶在视口底部，列表数据回来后页脚被推出视口，这次"可见元素位移"被计了分。

修法：给 `main` 一个 `min-height: calc(100dvh - var(--header-height))`，页脚永远在首屏之外，不再随内容长短移动。修完 0.069 → **0.000**。

代价是短内容页面下方会留一块空白（详情页与错误态可见）。这是有意识的取舍：**留白不影响可用性，跳动影响体验指标**。

- 没有对 `tokens.css` 之外的内联颜色做主题化（当前也不需要）。

## 6. 无障碍

### 6.1 键盘路径（实测 Tab 顺序）

1. `跳过导航` 跳转链接（聚焦时从顶部滑出，直接跳到 `#main`）→
2. 品牌链接 → 3. `启事列表` → 4. `发布启事` → 5. `+ 发布启事` → 6. 筛选控件（类型/状态/分类/关键词/重置）→ 7. 每张卡片（`RouterLink`，整卡可点、`Enter` 生效）→ 8. 分页按钮（带 `aria-current`）。

- 焦点环全局 `:focus-visible` 2px + 2px offset，从不 `outline: none`（仅鼠标点击时隐藏）。
- `main` 带 `tabindex="-1"` 作为跳转落点，且该元素聚焦时不显示焦点环（它不是控件）。
- 弹层/下拉一律用原生元素（`<details>` 未使用，也没有自定义弹窗），所以不需要手写焦点陷阱——**这是刻意的：不写焦点陷阱就不会写错**。

### 6.2 读屏

- 地标：`header` / `nav[aria-label="主导航"]` / `main#main` / `footer`。
- 标题层级：列表页 `h1 → h2`（每张卡片）；详情页 `h1 启事详情 → h2 记录标题 → h3 详细描述 → h2 匹配区`；提交页 `h1 发布启事`。**没有跳级**。
- 表单：`label[for]` ↔ `id` 全部配对；单选组用 `fieldset/legend`；错误用 `aria-invalid` + `aria-describedby` 关联到 `#field-{name}-error`；校验失败摘要 `role="alert"`。
- 加载：`role="status"` + `aria-busy="true"` + `.sr-only` 文案（"正在加载启事列表，请稍候"）。
- 匹配结果：结果摘要 `role="status"`；候选列表是 `<ol>`，顺序天然可读。
- 徽标：文字 + 色点 + 底色，不依赖颜色。

### 6.3 对比度

见 §2.1 的实测表，全部达到 WCAG 2.1 AA（正文 4.5:1、控件边界与焦点环 3:1）。两处是被检查逼着改的（`--color-text-subtle`、`--color-control-border`）。

### 6.4 动效

`prefers-reduced-motion: reduce` 下全局动画/过渡降到 0.01ms，骨架 sheen 直接 `display: none`，分值条无 transition。实测分值条 `transition-duration = 1e-05s`。

### 6.5 还没解决

- **没有跑过自动化 axe 审计**（不引新依赖）。上面每一条都是手工核对 + DOM 断言，不是审计分数。
- **页面标题（`document.title`）不随路由变化**，读屏切换页面时听不到"现在是详情页"。建议加 `meta.title` 或路由守卫里改 `document.title`（一行代码，但属于行为改动，留给人类决定）。
- 状态流转按钮点击后只有按钮禁用，**没有 `aria-live` 播报"状态已更新"**；成功后详情会重新拉取，视觉上状态徽标变化足够，但读屏用户可能不知道发生了。建议后续补一条 `role="status"`。
- 表单错误摘要里点条目会 `scrollIntoView` + 聚焦，实测可用；但 `focus({preventScroll:true})` 后再 `scrollIntoView` 的顺序在 Safari 上需要复核（未测 Safari）。

## 11. v2 增补：身份 · 置信度 · 通知

> **适用范围**：v2 新增的登录、我的启事、通知、三档配对卡片、授权交互与匿名遮蔽态。v1 的三个页面（列表 / 详情 / 发布）只做“加登录态、加遮蔽、加手机号提示”三处增量，不重做。
>
> **基线**：`main @ 21784f6` → 本任务分支 `feat/v2-A3-ui-baseline`。本文不改 `web/` 一行代码；所有稿面是 `docs/ui/v2/` 下的静态 HTML + PNG，数据全部虚构。
>
> **事实边界（重要）**：本章是**设计规格**，不是实现报告。v2 页面尚未编码，因此**没有** v2 的 LCP/INP/CLS、包体积、axe 分数或真机数据；v1 的实测值（§5）不能直接套到新页面上。实现后按 §5.1 的方法复测，结果写进 E2/D2 的交付评论，而不是补进本文冒充已测。

### 11.1 页面、路由与归属

| 路由 | 页面 | 实现归属 | 登录要求 | 本文章节 |
|---|---|---|---|---|
| `/login` | 登录 | B3 | 否 | §12 |
| `/my` | 我的启事（含匹配条数与三种分析状态） | D2 | 是 | §13 |
| `/notifications` | 通知（含未读红点、空态） | D2 | 是 | §14 |
| `/records/:id` | 详情：三档配对卡片、授权入口、匿名遮蔽 | E2 / C2 | 读否，写是 | §15–§17 |

### 11.2 导航与登录态

**桌面（≥768）**：`启事列表 / 我的启事 / 通知 / 发布启事 / 登录（或 用户名 + 退出登录）`。当前页用底色 + 字重 + `aria-current="page"` 三通道，不只换颜色。

**窄屏（<768）**：品牌 `FI` 即“启事列表”入口；导航只留 `我的（未登录时为“登录”）/ 通知 / 发布`。**不做底部 Tab 栏**——v1 的页脚、安全区和 `100dvh` 已经稳定，新增一条固定底栏会牵动所有页面的底部留白与键盘遮挡，收益不如风险大。

- 通知角标：未读数 >0 时渲染 16px 红底白字数字，并给 `aria-label="通知，N 条未读"`；为 0 时**不渲染**角标（不显示“0”）。
- 登录后显示 `陈同学`（头像首字），点名字进入 `/my`；“退出登录”放在 `/my` 的页脚或用户菜单里，不占顶栏横向空间。
- 401（会话过期）：任何需要登录的请求失败后，跳 `/login?redirect=<当前站内路径>`，登录页显示一条 `登录已过期，请重新登录。` 的信息条；**只接受站内相对路径**，不信任外部 URL。
- 登录页不渲染全局导航（避免出现点进去又被打回的入口），只保留品牌与“返回启事列表”文本链接。

| 能力 | 匿名 | 登录·非所有者 | 所有者 |
|---|---|---|---|
| 列表 / 详情标题、类型、状态、分类、时间 | 可见 | 可见 | 可见 |
| 描述、地点细节、发布者全名 | 遮蔽（§17） | 完整 | 完整 |
| 联系方式 | 遮蔽（§17） | **不显示**（不是该 pair 的一方） | 本人那一端可见；对方那一端按档位与授权 |
| 匹配区与三档卡片 | 遮蔽提示（仅 CTA） | **不渲染** | 可见 |
| `/my`、`/notifications` | 跳登录 | 可用（只看自己的） | 可用 |
| 发布、改状态、关闭启事 | 跳登录 | 拒绝（不是本人） | 允许 |
| 公开 / 撤回自己的联系方式 | 否 | 否 | 仅中档、仅自己那一端 |

**匹配区默认按“仅发布者可见”设计**。这是 A3 的 UI 假设，A1 的 17 接口权限矩阵是最终事实源；如果 A1 允许登录非所有者查看他人的匹配区，必须重新评估信息暴露（配对卡片会同时出现两条启事的摘要与联系方式状态），并另出一稿，不能在当前稿上直接放开。

### 11.4 术语与命名边界

| 词 | 定义 | 用在哪 | 不要写成 |
|---|---|---|---|
| **可能相关** | 候选对象在用户界面的唯一称呼 | 标题、条数、通知、空态、按钮附近 | 任何近义改写；禁止词表由 A2 单独维护，本文不重复列出，避免文档自身成为违规样本 |
| **置信度** | v2 配对分数，0–1，界面显示整数百分比 | 配对卡片、档位轨、通知 | 与“相似度”混用 |
| **相似度** | v1 `/api/match` 的文本相似分数 | 详情页 v1 匹配区（若保留） | 拿来当 pair 的置信度 |
| **配对（pair）** | 一条寻物 ↔ 一条招领的 1:1 匹配单元 | `/my` 条数、卡片、通知 | “已解决”“锁定”“占用” |
| **记录状态** | `PENDING / COMPLETED / CLOSED` 的唯一中文映射：进行中 / 已完成 / 已关闭 | `/my` 卡片、详情页页头、状态矩阵稿 | 旧状态词；把「已完成」当「已关闭」的同义词 |
| **授权** | 本人在中档 pair 里公开自己的联系方式 | 开关、附言、撤回 | “解锁”“申请”“审批” |
| **遮蔽** | 匿名浏览时用占位块替代真实字段 | 详情页 | “打码”（打码是后端写入前的脱敏，不是 UI 占位） |
| **撤回** | 关闭授权并清空附言 | 授权交互 | “删除”（不删除启事，也不删除配对） |

两个“锁定”要分开：**登录锁定**是安全策略（§12），**不是**配对状态；配对只有 `NEW / CONTACTED / IGNORED`，没有“已解决”，也没有任何跨 pair 的锁定语义。

### 12.1 结构

```
/login（独立页，无全局导航）
  [FI] 校园失物招领
  ┌ 登录 ─────────────────────────────┐
  │ 用学号和密码登录，查看你发布的启事、  │

- 卡片宽 `min(400px, 100% - 32px)`，内距 `--sp-5`（20）→ ≥768 为 `--sp-6`；页面顶部留 `clamp(24px, 8vh, 72px)`，**不强制垂直居中**（移动端键盘弹起后居中会把卡片顶出视口）。

### 12.2 状态矩阵

| 状态 | 触发 | 视觉 | 文案 | 焦点 / 播报 |
|---|---|---|---|---|
| 默认 | 进入页面 | 白卡片、空字段、主按钮可用 | 见 §12.3 | 不自动聚焦（移动端不弹键盘） |
| 提交中 | 点登录且客户端校验通过 | 按钮转圈 + “登录中…”，按钮与输入框禁用 | `登录中…` | 不重复提交；`aria-busy="true"` |
| 字段为空 | 提交时学号/密码为空 | 顶部摘要 + 字段红框 + `!` 文案 | `请填写学号和密码。` / `请输入学号。` / `请输入密码。` | 焦点落到第一个空字段 |
| 凭证错误 | 401 或业务错误码 | 页级红条（`role="alert"`） | `学号或密码不正确，请重新输入。` | **保留学号、清空密码**，焦点落到密码 |
| 锁定 | B2 判定连续失败过多 | 页级黄条 + 倒计时；输入框与按钮禁用 | `登录已暂时锁定` / `尝试次数过多。请在 {倒计时} 后再试，或联系课程助教。` / 按钮 `已锁定 · {倒计时}` | 只播报一次；倒计时视觉更新不每秒打断读屏 |
| 网络 / 服务失败 | 超时、5xx、断网 | 页级红条 + “重试” | `登录服务暂时不可用，请稍后重试。` | 焦点不动；**不能显示成“密码错误”** |
| 会话过期 | 401 后带 `redirect` 回到登录 | 页级信息条（`role="status"`） | `登录已过期，请重新登录。` | 登录成功后回 `redirect` 指向的站内路径 |

### 12.4 锁定规则

- **阈值与时长由 B2 定**，UI 不写死“5 次 / 10 分钟”。前端只消费 `retryAfterSeconds`（或等价字段）并显示倒计时；倒计时归零后重新启用表单，前端**不自行解锁**——下一次提交仍由服务端判定。
- 倒计时格式 `mm:ss`；视觉每秒更新，`aria-live` 不逐秒播报。进入锁定态时用 `role="alert"` 播报一次；剩余 ≤60 秒时再播报一次“还可尝试时间不足 1 分钟”；归零时用 `role="status"` 播报“可以重新登录了”。
- 锁定态下不隐藏“联系课程助教”的出路；不显示“账号已封禁”这类无法行动的词。

### 12.5 交互与无障碍

- `label[for]` ↔ `id` 配对；学号 `autocomplete="username" inputmode="numeric" spellcheck="false"`，密码 `autocomplete="current-password"`。
- “显示密码”是真实 `<button type="button">`，`aria-pressed` 表示当前是否明文；不改变字段值。触控目标 ≥40px。
- 回车提交；提交中禁用按钮并阻止重复提交；失败后保留已填内容（密码除外，凭证错误时必须清空）。
- 错误摘要 `role="alert"`；字段错误 `aria-invalid` + `aria-describedby` 指向 `#login-{field}-error`。
- 对比度全部复用 v1 token：主按钮白字 / `--color-primary` 6.70:1；错误红字 / `--color-danger-soft` 4.78:1；锁定黄字 / `--color-warning-soft` 5.76:1；控件描边 3.06:1。
- 320px：卡片满宽减 32px，字段与按钮满宽；长学号（20 位）不换行撑破，输入框内部横向滚动即可。

### 12.6 依赖

- B2：登录接口、错误码、锁定阈值/剩余时间字段、会话 TTL。
- B3：`/login` 路由、`redirect` 参数白名单（只允许 `/` 开头的站内路径）、401 拦截与回跳。
- A1：`401` 与“锁定”对应的状态码口径；UI 不解析具体数字，只按 B2 给的 `error.code` 分支。

## 13. 我的启事 `/my`

### 13.1 结构

```

record-row × N   ┌ 左：类型/状态/#id/标题/分类·地点·时间/操作

### 13.2 每条记录的组成

| 元素 | 内容 | 说明 |
|---|---|---|
| 类型徽标 | 寻物 / 招领 | 复用 `RecordTypeTag` |
| 状态徽标 | 进行中 / 已完成 / 已关闭 | 复用 `RecordStatusTag`；三态都可达，`已完成` 与 `已关闭` 的文案与颜色必须能区分 |

| 标题 | 记录标题 | `h2`，可换行；`overflow-wrap: anywhere` |
| 元信息 | 分类 · 地点 · 发生时间 | 单行，窄屏换行 |
| 操作 | 查看详情 / 关闭启事 | 关闭只对本人、只对未关闭记录显示 |
| 匹配摘要 | 条数 + 状态 + 说明 + 入口 | 见 §13.3 |

### 13.3 匹配分析的三种状态（+ 一种错误态）

| 状态 | 服务端依据（建议字段） | 视觉 | 条数 | 主文案 | 动作 |
|---|---|---|---|---|---|
| **分析中** | `analysisStatus = ANALYZING` | 信息色小转圈 + 文字 | 不显示（或 `—`） | `正在比对候选启事，通常几秒内完成。离开页面不会中断分析。` | 查看详情；可离开 |
| **已出结果** | `DONE` | 成功色实心点 + `已出结果` | 大号数字 + `条可能相关` | `{n} 条配对相互独立；处理其中一条，其余配对不受影响。` | 查看可能相关 |
| **已降级** | `DEGRADED`（引擎落 `LOCAL_KEYWORD`） | 警告色实心点 + `已降级` | 大号数字 + `条可能相关` | `AI 服务暂不可用，本次改用本地关键词分析；结果可能不够准，请结合描述自行核对。` | 查看可能相关；重试分析 |
| **分析失败**（错误态） | `FAILED` | 危险色 + `分析失败` | 不显示 | `本次分析没有完成。可以重试，或稍后再看。` | 重试分析 |

- **三种状态是任务要求的常规状态**；“分析失败”是独立的错误路径，不混进这三种，避免把“服务失败”说成“已降级”。
- `已降级`**不是失败**：结果仍然可用、可查看、可授权；只是引擎与解释质量降级。页面必须给出“可能不够准”的提示和“重试分析”，不能只改一个颜色。
- 条数只来自服务端的 `matchCount`（配对数），**不要用前端数组长度冒充**；未知时宁可不显示数字，也不显示 `0`。
- 状态文案旁边必须有文字，不能只靠转圈/色点；转圈 `aria-hidden`，状态文本进 `role="status"`（分析完成时播报一次）。

### 13.4 多配对共存（人类 2026-10-27 已拍板）

- 一条启事可以同时与多条对方启事各自形成 1:1 配对；`3 条可能相关` = 3 个独立 pair，不是“3 条记录被占用”。
- 每条 pair 的 `NEW / CONTACTED / IGNORED` 各自独立；标记/忽略一条**不改变**其它 pair，也**不改变** `t_record.status`。
- 不存在“已解决”状态；不在 UI 里写“已解决”“锁定”“占用”。卡片上的“已联系 / 已忽略”只是这一条 pair 的进展。
- 当条数 ≥2 时，匹配摘要下方固定一行：`{n} 条配对相互独立；处理其中一条，其余配对不受影响。`（数字随实际条数变化）。

### 13.5 关闭启事

- 只能由发布者本人操作；系统不按时间、匹配成功、被联系自动关闭。
- 点击“关闭启事”弹原生 `<dialog>`：
  - 标题：`关闭这条启事？`
  - 正文：`关闭后，这条启事会标记为已关闭；系统不会自动关闭或恢复，只有你能操作。已有配对仍可查看。`
  - 按钮：`关闭启事`（danger）/ `取消`（ghost）
- `<dialog>` 原生焦点陷阱与 `Esc` 关闭；关闭成功后 `role="status"` 播报 `已关闭。`，列表行状态徽标更新；不整页刷新。
- 关闭后是否允许重新打开由 `allowedStatuses` 决定；UI 只渲染后端给的可选状态，**不自行推导**。

### 13.6 空态、加载、错误、分页

| 状态 | 视觉 | 文案 |
|---|---|---|
| 加载 | 3 个与记录行同构的骨架（徽标行 + 标题 + 元信息 + 右侧块），`aria-busy` | 读屏“正在加载我的启事” |
| 空 | `.empty` 虚线框 + 32×3 品牌短横 | `还没有发布过启事` / `你还没有发布过启事。发布后，这里会显示可能相关的条数。` / `去发布启事` |
| 错误 | `ErrorBanner` + 重试 | `加载失败` + `重试` |
| 分页 | 复用 `PaginationBar` | 当前页 `aria-current="page"` |

### 13.7 响应式与无障碍

- 320px：记录行单列；标题换行；匹配摘要的数字与状态不并排挤成两行；操作按钮换行；无横向滚动。
- 标题层级：`h1 我的启事` → 每条记录 `h2`；匹配摘要不另起 `h2`，用 `p`/`span` + `aria-label`，避免读屏听到一串同级标题。
- 条数用 `aria-label="{n} 条可能相关"`，视觉上的大数字 `aria-hidden`，避免读屏把“3”和“条可能相关”拆成两个孤立信息。
- 关闭对话框、重试、分页按钮全部键盘可达，焦点可见。

## 14. 通知 `/notifications`

### 14.1 结构

```
page-head        通知 + 说明 + [全部标为已读]（未读为 0 时禁用）
tabs             全部 N / 未读 N
notif-list       行 × N（整行是一个链接）
pagination       PaginationBar
```

行解剖：`未读点(8px) | 标题 + 描述 | 相对时间`。整行是 `<a>`，点击进入对应启事/配对；不在行内再放第二个按钮。

### 14.2 未读：三通道，不只红点

- 视觉：8px 红点 + 标题加粗 + 行浅蓝底（`--color-primary-softer`）。
- 读屏：整行 `aria-label="未读：{标题}"`；未读角标/红点本身 `aria-hidden`，避免重复播报。
- 顶栏角标：`通知` 旁 16px 红底白字数字（未读数），`aria-label="通知，N 条未读"`；0 时角标不渲染。
- 点开一条即标记已读（乐观更新）；失败时回滚并给一条 `标记已读失败，请重试。` 的 `role="alert"` 提示，不静默失败。

### 14.3 通知类型与文案模板

| 类型 | 触发 | 标题 | 描述 | 去向 |
|---|---|---|---|---|
| `MATCH_NEW` | 你的启事出现新的可能相关结果 | `「{title}」有 {n} 条新的可能相关启事` | `置信度分别为 {列表}。`（最多列 3 个，其余用“等 N 条”） | 详情页 `#match` |
| `CONTACT_UNLOCKED` | 对方在中档 pair 里公开了联系方式 | `{name} 公开了联系方式` | `在「{title}」#{a} ↔ #{b} 的配对中，对方已公开手机号，现在可以查看。` | 该 pair 所在详情 |
| `ANALYSIS_DEGRADED` | 分析降级为本地关键词 | `「{title}」的分析已降级` | `AI 服务暂不可用，本次改用本地关键词分析；结果可能不够准，可以稍后重试。` | 详情页 / `/my` |
| `PAIR_STATUS` | 本人标记/忽略配对后的回执 | `你标记了一条配对为「已联系」`（或“已忽略”） | `「{title}」#{a} ↔ #{b} 已更新；其余配对不受影响，记录状态没有改变。` | 该 pair 所在详情 |

- `{name}` 用发布者称呼（`林同学`），没有则用 `对方`；**不展示手机号**，通知只说“已公开”，号码到详情页按档位看。
- 相对时间：<1 分钟“刚刚”，<24 小时“N 分钟前 / N 小时前”，其余“昨天 HH:mm / 10 月 21 日”；`<time datetime>` 带绝对时间，鼠标悬停可见。
- 保留策略（多少天清理）**不在本文定义**，由 D2/A1 决定；UI 不显示未定义的承诺。

### 14.4 状态

| 状态 | 视觉 | 文案 |
|---|---|---|
| 加载 | 4 行骨架，宽度与真实行一致 | 读屏“正在加载通知” |
| 未读 >0 | 红点 + 加粗 + 浅底 | `全部标为已读` 可用 |
| 未读 =0 | 无红点；按钮禁用（`aria-disabled`） | `暂无未读通知`（仅在“未读”tab 空时） |
| 空（全部 0） | `.empty` | `暂无通知` / `当你的启事出现新的可能相关结果，或对方在配对里公开了联系方式，这里会出现提醒。` / `回到启事列表` |
| 错误 | `ErrorBanner` + 重试 | `通知加载失败` + `重试` |
| 全标已读失败 | 行恢复未读 + 页级红条 | `操作失败，请重试。` |

“全部标为已读”用乐观更新：点击后立即全部变已读、角标归零；失败则**整批回滚**并提示。不要逐条回滚到一半，用户无法判断最终状态。

### 14.5 无障碍与响应式

- 行是链接，焦点环可见；`aria-label` 包含“未读”与标题，避免红点信息丢失。
- `tabs` 是导航链接，不是 ARIA tablist；用 `aria-current="page"`，减少键盘方向键的额外约定。
- 320px：时间移到标题下方（不挤在右侧）；标题与描述换行；红点固定在左上角，不随文字高度居中漂移。
- 空态的“回到启事列表”是真实链接；没有“清除筛选”之类无意义动作。

## 15. 三档配对卡片

### 15.1 档位定义（边界写死，配置可调）

| 档位 | 置信度 | 界面名称 | 对方字段 | 联系方式 | 授权入口 |
|---|---|---|---|---|---|
| 高 | **≥ 0.90** | 高置信度 | 标题、分类、地点、时间、命中依据 | **双方直接可见**（无需授权） | **无**（不需要） |
| 中 | **0.75 ≤ x < 0.90** | 可授权查看 | 同上 | 只显示本人这一端；对方显示“对方尚未公开” | **有**，仅本人、仅本 pair |
| 低 | **< 0.75** | 仅显示条数 | **不返回、不渲染** | 无 | 无（接口 403） |

- `0.90` 归**高档**（“直看 0.90”是 A1 的配置默认值）；`0.75` 归**中档**。这条边界由 A1 契约冻结，UI 不再解释。
- **档位由服务端下发**（建议 `tier: DIRECT | AUTHORIZABLE | COUNT_ONLY`）。前端**不按 `scorePercent` 二次分档**：`0.896` 显示成 `90%` 时，如果前端拿显示值判档，就会把中档错画成高档。置信度原值 `score`（0–1）只用于展示与日志，判档用服务端给的 `tier`。
- 低档不返回对方任何字段；**不是**前端拿到全量数据后用 CSS 遮住。UI 只拿 `lowCount`。
- 分档只决定**可见性与动作**，不参与排序，也不改变记录状态；排序仍由服务端按置信度降序给。

### 15.2 卡片解剖

```
┌ ①1 ②[高置信度] ③置信度 92% ④[新配对] ─────────── #13 ↔ #27 ┐
│ ┌ 寻物方 · 你的启事 ────────┐  ↔  ┌ 招领方 · 对方启事 ───────┐ │
│ │ [寻物] [进行中]            │     │ [招领] [已完成]            │ │
│ │ 黑色钱包（图书馆三楼）       │     │ 图书馆拾到黑色钱包…        │ │
│ │ 钱包卡证 · 图书馆三楼 · 15:00│     │ 钱包卡证 · 图书馆三楼 · 15:40│ │
│ │ ┌ 我的联系方式 ─────────┐ │     │ ┌ 对方联系方式 ─────────┐ │ │
│ │ │ 138 0000 1234  已公开 │ │     │ │ 139 0000 5678  已公开 │ │ │
│ │ └───────────────────────┘ │     │ └───────────────────────┘ │ │
│ └───────────────────────────┘     └───────────────────────────┘ │
│ 判断依据：黑色钱包、图书馆三楼、10 月 20 日下午…                  │
│ [查看对方启事] [标记为已联系] [忽略这条]        只影响这一条配对  │
│ 高置信度只代表描述相似…请自行核实。                                │
└──────────────────────────────────────────────────────────────────┘
```

① 名次（`aria-hidden`，列表顺序本身可读）② 档位徽标 ③ 置信度（`tabular-nums`）④ 配对状态 ⑤ 两端摘要 ⑥ 联系方式条 ⑦ 判断依据（左侧 2px 竖线）⑧ 动作与“只影响这一条”提示。

- 卡片左侧 3px 色条按档位着色（高 success / 中 warning / 低 text-subtle），与 v1 记录卡的类型色条同一手法：`inset box-shadow` 或绝对定位的 `::before`，不占内宽。
- 两端用一条竖线 + `↔` 连接；<860px 改为上下堆叠，连接符隐藏，中间用横线分隔。**不做左右滑动**：滑动手势与读屏、键盘都不友好。
- 卡片本身不是链接（里面已有多个按钮）；标题可点“查看对方启事”。整卡可点会让“公开联系方式”这类按钮的点击语义变得危险。

### 15.3 三档的行为差异

| 行为 | 高档 | 中档 | 低档 |
|---|---|---|---|
| 显示对方标题 / 地点 / 时间 | 是 | 是 | **否** |
| 显示对方联系方式 | 是（无需授权） | 否（“对方尚未公开”） | **否** |
| 显示本人联系方式 | 是 | 是（仅本人可见；可公开） | 否 |
| 授权开关 | 无 | 有（仅本人） | 无 |
| 标记已联系 / 忽略 / 查看对方启事 | 有 | 有 | 无（只有补充描述 / 重新分析） |
| 卡片形态 | 双端卡 | 双端卡 + 授权区 | **计数块**，不是卡片 |
| 空态 | “暂无高置信度结果” | “暂无可授权查看的结果” | “没有更多低置信度结果” |

### 15.4 高档：正常 / 禁用 / 空 / 降级

| 状态 | 触发 | 界面 | 动作 |
|---|---|---|---|
| 正常 | `tier=DIRECT`，pair `NEW`，记录未关闭 | 双端联系方式都显示，档位徽标 success，说明“高置信度：双方可直接查看联系方式，无需授权。” | 查看 / 标记已联系 / 忽略 |
| 禁用 | pair 已 `CONTACTED`/`IGNORED`，或记录 `CLOSED` | 卡片保留、号码保留（历史回看）；动作置灰并给出可见理由 | `已联系，这条配对只读；号码仍可见，方便回看。` / `启事已关闭，不能再更改配对状态。` |
| 空 | 没有 ≥0.90 的结果 | `.empty`：“暂无高置信度结果” / “没有 ≥90% 的可能相关；中档与低档结果不受影响。” | 无 |
| 降级 | pair `engine=LOCAL_KEYWORD`，分数仍 ≥0.90 | 卡片顶部一条黄色说明：“AI 服务暂不可用，本次由本地关键词引擎分析，置信度可能偏低。” 号码与动作仍可用 | 查看 / 标记 / 忽略 / 重试分析 |

高档仍要显示“请自行核实对方身份与号码”；**“高置信度”不是“已验证”**。不要把档位徽标写成“安全”“可信”“已验证”。

### 15.5 中档：正常 / 禁用 / 空 / 降级

| 状态 | 触发 | 界面 | 动作 |
|---|---|---|---|
| 正常 | `tier=AUTHORIZABLE`，pair `NEW`，记录未关闭 | 本人侧：“我的联系方式 · 未公开” + `公开我的联系方式`；对方侧：“对方联系方式 · 对方尚未公开”；档位徽标 warning | 公开（仅本人）/ 查看 / 标记 / 忽略 |
| 禁用 | 记录 `CLOSED` | 开关与撤回禁用，说明：“启事已关闭，不能再公开或撤回；已公开的号码仍对对方可见。” | 查看（只读） |
| 空 | 没有 0.75–0.89 的结果 | `.empty`：“暂无可授权查看的结果” / “没有 75%–89% 的可能相关；高档与低档结果各自独立。” | 无 |
| 降级 | `engine=LOCAL_KEYWORD` | 顶部黄色说明：“本次由本地关键词引擎分析，置信度可能偏低；公开前请先核对。” 授权仍可用 | 公开 / 查看 / 标记 / 忽略 / 重试分析 |

- “只有本人能公开自己的联系方式”在界面上的落点：开关只出现在“我的联系方式”一侧；对方侧永远没有按钮。**不做“帮对方公开”“申请查看”**。
- 对方未公开时固定文案 `对方尚未公开`；不写“无权限”“403”“未授权”，也不把它渲染成错误条。它是正常的等待状态。
- 本人未公开时，本人仍能看到自己的号码（“仅你可见”），但必须用状态文字说明“对方看不到”，避免误以为已经公开。

### 15.6 低档：正常 / 禁用 / 空 / 降级

| 状态 | 触发 | 界面 | 动作 |
|---|---|---|---|
| 正常 | `tier=COUNT_ONLY`，有低档候选 | 计数块：大号数字 + `条可能相关`；标题“置信度不足，暂不展示详情”；说明低于 75%、不返回对方字段 | 补充描述 / 重新分析 |
| 禁用 | 分析中 | 数字位显示 `—`，标题“正在分析，暂不能查看条数”；不展示任何对方字段 | 无（补充描述可先不做） |
| 空 | 没有 <0.75 的候选 | `.empty`：“没有更多低置信度结果” / “当前没有低于 75% 的候选；这不影响高、中档结果。” | 无 |
| 降级 | `engine=LOCAL_KEYWORD` | 黄色说明：“AI 服务暂不可用，本次用本地关键词分析；低档仍然只给条数。” 计数保留 | 重试分析 |

低档的“空”与“禁用”容易混：**空是没有候选，禁用是还在算**。两者都不出现对方字段，但文案与数字位不同。

### 15.7 状态矩阵（稿面 `state-matrix.png`）

| 档位 | 正常 | 禁用 | 空 | 降级 |
|---|---|---|---|---|
| 高 | 双端可见 + 动作可用 | 已联系/记录关闭 → 只读 + 理由 | 暂无高置信度结果 | 黄色降级说明 + 结果仍可用 |
| 中 | 本人可公开 + 对方未公开 | 记录关闭 → 开关/撤回禁用 | 暂无可授权查看的结果 | 黄色降级说明 + 授权仍可用 |
| 低 | 只给条数 | 分析中 → 条数待定 | 没有更多低置信度结果 | 黄色降级说明 + 只给条数 |

**禁用态的通用规则**：不要只给 `disabled` 把按钮变成不可聚焦的黑洞。用 `aria-disabled="true"` + 阻止提交 + 一段可见理由（`id` 由 `aria-describedby` 关联），让键盘用户能聚焦并听到“为什么不能点”。

### 15.8 多配对：卡片之间互不影响

- 同一详情页可以同时出现 3 张不同档位的卡片，每张有自己的 `pairId`、`status`、`score`、`tier`。
- 标记/忽略/授权都带 `pairId`，请求成功只更新这一张卡；**不重排、不刷新其他卡**，避免用户失去位置。
- 卡片头部 `#13 ↔ #27` 是两端记录 ID，不是 pair ID；pair ID 可以放在 `data-pair-id` 或详情链接里，不必展示给用户。
- 不存在“处理完一条后其余变灰/锁定”的联动；如果后端返回了这种联动，是后端 bug，不是 UI 要适配的行为。

### 15.9 与 v1 `/api/match` 结果的区别

| 项 | v1 `/api/match` | v2 配对卡片 |
|---|---|---|
| 分数名 | 相似度（`scorePercent`） | 置信度（`score` → `scorePercent`） |
| 来源 | 关键词/向量文本相似 | LLM 语义比对 + 兜底本地引擎 |
| 用途 | 帮用户找候选 | 决定联系方式可见性、是否可授权 |
| 分档 | 只影响进度条颜色（≥70/≥40） | 决定档位、按钮、字段是否返回 |
| 阈值 | `minScore` 默认 0.30 | 0.90 / 0.75，服务端配置 |
| 组件 | `MatchItemCard`（整卡链接） | `PairCard`（多动作，非整卡链接） |

**不要把 v1 的相似度进度条直接塞进 v2 卡片**：两者语义不同，同屏出现两个百分比会让人以为是同一件事。若详情页同时保留 v1 匹配区，必须在标题里写清“相似度”与“置信度”的区别，或干脆在 v2 详情页移除 v1 匹配区（推荐后者，前提是 E2 确认没有入口依赖）。

### 15.10 数据契约（UI 需要，字段名以 A1 为准）

| 语义 | 类型 | 用途 |
|---|---|---|
| `pairId` | string | 动作幂等键、DOM key |
| `tier` | `DIRECT \| AUTHORIZABLE \| COUNT_ONLY` | 档位；前端不自行计算 |
| `score` / `scorePercent` | number 0–1 / integer 0–100 | 展示；**不用于判档** |
| `engine` | `EXTERNAL_LLM \| LOCAL_KEYWORD` | 降级说明 |
| `pairStatus` | `NEW \| CONTACTED \| IGNORED` | 状态徽标、动作可用性 |
| `lost` / `found` | 记录摘要（标题、类型、状态、分类、地点、时间、发布者称呼） | 两端展示；低档不返回 |
| `myContactVisible` / `theirContactVisible` | boolean | 联系方式条；**服务端判**，前端不根据 user id 猜 |
| `myContact` / `theirContact` | `{ value?: string }` | 未公开时**不返回 value**；不是前端遮住 |
| `canAuthorize` / `canWithdraw` | boolean | 开关与撤回；仅本人、仅中档、记录未关闭 |
| `degraded` | boolean | 黄色说明；与 `engine` 二选一，建议只留一个 |
| `lowCount` | number | 低档条数；没有低档时不返回或 0 |

**缺字段时的降级**：`tier` 缺失 → 不渲染卡片，显示区级错误“匹配结果加载失败”+ 重试，**不要**用 `scorePercent` 猜档；`myContact.value` 缺失但 `canAuthorize=true` → 只显示开关，不显示号码；`score` 缺失 → 只显示档位，不显示百分比。

## 16. 授权交互（公开 / 撤回 + 附言）

### 16.1 出现条件

| 档位 | 开关 | 说明 |
|---|---|---|
| 高 ≥0.90 | 无 | 双方直接可见；没有“隐藏”入口（这是产品口径，不在 UI 层加例外） |
| 中 0.75–0.89 | 有，仅本人一侧 | 未公开 → 可公开；已公开 → 可撤回 |
| 低 <0.75 | 无 | 接口 403；UI 不渲染入口，也不显示“无权限” |

另外三个前提：已登录、是启事发布者本人、记录未关闭。任一不满足 → 不渲染授权区（不是渲染后禁用）。

### 16.2 开关行为

```
未公开： [ ○ ] 公开我的联系方式        未公开
已公开： [ ● ] 公开我的联系方式        已公开    [撤回公开]
```

- 未公开时打开开关 → **展开附言表单**（不是立即公开）；必须点“保存并公开”才发请求。理由：公开号码是隐私操作，给用户一次确认附言的机会，也避免误触。
- 表单展开后把开关关掉：附言为空 → 直接收起；附言非空 → 弹“放弃未保存的附言？”确认（避免误触丢字），确认后才收起。未产生副作用，不需要走撤回流程。
- 已公开时点“撤回公开” → 弹确认（§16.4），确认后发撤回请求；**不是**点一下开关就撤回。
- 请求中：开关与按钮禁用，按钮转圈“保存中…”；请求失败：开关回到原状态、附言**保留**、页级红条“保存失败，请重试。你的附言还在。”。
- 公开成功后：`role="status"` 播报 `已公开，对方现在可以查看。`；开关保持开，附言折叠为只读摘要（避免用户以为没保存）。

### 16.3 附言：≤200 字

- 标签 `附言（选填）`；计数器 `{n}/200`，`tabular-nums`，靠右；达到 200 时计数器加粗并提示 `已达 200 字上限`。
- `textarea maxlength="200"`；粘贴超长时**截断到 200** 并显示 `已截断到 200 字。`（`role="status"` 播报一次），不让用户以为内容完整保存。
- 服务端仍会校验 200 上限；如果服务端拒绝，字段级错误固定为 `附言最多 200 字，请删减 {n} 字后再保存。`，`aria-invalid="true"` + `aria-describedby` 关联，焦点落到 textarea。
- 字数按 **Unicode 码点**计（`[...value].length`），与后端同口径；换行计入，连续空格不折叠显示（`white-space: pre-wrap`）。
- 提示固定：`会随授权一起展示给对方；撤回时一并清空。请勿填写与配对无关的隐私信息。`
- 附言会过 A1 的打码规则（手机号/QQ/证件号/相对时间等）；UI 不自己发明打码正则，但要在预览里显示“打码后”的文本——**预览即对方看到的文本**，不能预览原文、后端再打码。

**超限提示的三种入口**都要有：输入到 200（计数器提示）、粘贴超长（截断提示）、服务端拒绝（字段错误）。只做 `maxlength` 会让“为什么没保存”变成一个谜。

### 16.4 撤回：二次确认，附言清空

- 确认对话框（原生 `<dialog>`）：
  - 标题：`撤回公开？`
  - 正文：`撤回后对方将看不到你的联系方式；附言也会一并清空，无法恢复。撤回只影响这一条配对，其他配对与启事状态不变。`
  - 按钮：`确认撤回`（danger）/ `取消`（ghost）
- 撤回成功后：开关关闭、状态“未公开”、附言清空、`role="status"` 播报 `已撤回，对方将看不到你的联系方式。`
- 撤回**不**改变 pair 状态，**不**关闭启事，**不**影响其他 pair；不要顺手把“已联系”改回“新配对”。

### 16.5 权限与失败路径

| 场景 | 界面 | 文案 |
|---|---|---|
| 对方未公开 | 正常等待态，不是错误 | `对方尚未公开` + `对方公开后，这里会显示号码；你无法替对方公开。` |
| 低档请求被拒（403） | UI 不发起、不展示入口 | 若意外收到：区级提示 `这条候选的置信度不足，暂不能查看详情。`，不显示原始错误码 |
| 未登录 / 会话过期（401） | 跳登录，带回跳 | `登录已过期，请重新登录。` |
| 不是本人（403） | 不渲染入口；若意外触发 | `只有启事发布者本人可以公开联系方式。` |
| 记录已关闭 | 开关/撤回禁用 + 理由 | `启事已关闭，不能再公开或撤回；已公开的号码仍对对方可见。` |
| 网络失败 | 保留表单内容 + 重试 | `保存失败，请重试。你的附言还在。` |

**不要**把 403 原样显示成“Forbidden”，也不要把“对方尚未公开”做成红色错误。前者暴露系统词，后者把正常状态说成故障。

### 16.6 无障碍

- 开关：真实 `<input type="checkbox" role="switch">`，`aria-checked` 由浏览器维护；标签文字包含“公开我的联系方式”；旁边有“已公开/未公开”文字，不只靠开关颜色。
- 附言：`label[for]` + `aria-describedby` 指向提示与计数器；`aria-invalid` 只在服务端拒绝时置 true；错误 `role="alert"`。
- 撤回对话框：原生 `<dialog>` 的焦点陷阱与 `Esc`；打开时焦点落在“取消”（破坏性操作不默认聚焦确认）；关闭后焦点回到“撤回公开”按钮。
- 保存成功/失败用 `role="status"` / `role="alert"`，不要只改按钮文案。
- 触控目标 ≥40px；附言 textarea 最小高 76px；320px 下开关与文字换行不重叠。

## 17. 匿名遮蔽态

### 17.1 一条硬规则：不把真实数据发到匿名页面

遮蔽**不是** CSS 模糊、不是 `visibility: hidden`、不是把真实值放进 `title` 或 `data-*`。匿名响应对以下字段**根本不返回**；页面只渲染占位块。这样查看源码、读屏、复制文本都拿不到真实值。

| 字段 | 匿名 | 登录（非所有者） | 所有者 | 说明 |
|---|---|---|---|---|
| 标题 | 可见 | 可见 | 可见 | 标题是浏览与搜索的核心，不遮蔽 |
| 类型 / 状态 / 分类 / 时间 | 可见 | 可见 | 可见 | 不涉及身份 |
| 地点 | **截断** + “登录后可查看” | 完整 | 完整 | 截断算法由 C1/A1 定义；UI 不自造 |
| 详细描述 | **块级占位** | 完整 | 完整 | 不返回原文 |
| 联系方式 | **块级占位** | **不显示**（不是该 pair 的一方） | 本人那一端可见；对方那一端按档位与授权 | 手机号/QQ/微信都不返回给非 pair 方 |
| 发布者称呼 | **打码**（`林**`） | 完整 | 完整 | 打码规则由 A1 定义 |
| 可能相关的启事 | **遮蔽提示 + 登录 CTA** | 不渲染（非所有者） | 可见 | 匹配区 owner-only |
| 记录 ID | 可见 | 可见 | 可见 | 不是敏感信息 |

**地点截断的 UI 边界**：C1 可能返回“图书馆三楼…”这类已截断字符串，也可能返回 `locationMasked=true` + 一个短前缀；UI 只负责在截断值后加一个内联占位 `登录后可查看`，不自己按字符数切。否则前端与后端的截断规则会漂移。

### 17.2 两种占位形态

```
内联（地点）：地点：图书馆三楼 [登录后可查看]
块级（描述）：┌ 登录后可查看完整描述 ─────────────────┐
              │ 匿名浏览只显示标题与基本信息。描述、地点 │
              │ 细节与联系方式在登录后加载。            │
              │ [登录后查看]                           │
              └────────────────────────────────────────┘
块级（联系方式）：┌ 登录后可查看联系方式 ───────────────┐
                  │ 为保护发布者，号码不在匿名页面渲染； │
                  │ 登录后按档位规则展示。              │
                  └────────────────────────────────────┘
```

- 内联：`display:inline-flex`，`padding: 2px 8px`，虚线 1px，`--color-surface-muted` 底，12px 字；紧跟在截断值后面，不换行到下一段。
- 块级：满宽、虚线、浅底、内距 16；标题 14/500，描述 12px `--color-text-subtle`，动作按钮在左下。
- 统一视觉：虚线 + 浅底 + 文字“登录后可查看”；**不用锁形图标**（不引图标库，且锁会暗示“加密”而不是“未登录”）。
- 占位块不是按钮；只有内部的“登录后查看 / 去登录”是链接/按钮。整块可点会让读屏听到一个没有明确目标的链接。

### 17.3 登录 CTA 与回跳

- 匿名详情顶部一条信息条：`你正在匿名浏览` / `登录后可查看完整描述、联系方式与可能相关的启事。` / `去登录`。
- 所有“登录后查看”链接都带 `?redirect=` 当前站内路径；登录页只接受 `/` 开头的相对路径，拒绝 `//evil.com`、`https://…` 与反斜杠变体。
- 登录成功后回到原详情页并**定位到原来的区块**（描述 / 联系方式 / `#match`），不要一律回首页。
- 匿名用户只保留“发布启事”这一个会跳登录的入口，其余写操作不显示；点“发布”“我的启事”“通知”都会跳登录并带回跳。

### 17.4 读屏与安全

- 占位块用普通文本，读屏自然读出“登录后可查看…”；不要用星号，也不要在非交互块上挂一个会覆盖正文的 `aria-label`。
- 不在 DOM 中保留真实值的注释、`title`、`aria-label`、隐藏 input；服务端不返回是唯一可靠的做法。
- 页面标题仍是 `启事详情`，`h1` 不因为匿名而改变；避免读屏在“登录/未登录”两种状态下听到不同的标题层级。
- 匿名页不加载匹配接口；即使加载了，也只在服务端判定为所有者时才返回数据。前端不做“先拿全量再遮”的假遮蔽。

### 17.5 响应式

- 390 / 320 两个视口都渲染完整页面（稿面 `masked-board.png`）：320 下品牌文字收起、标题换行、占位块满宽、无横向滚动。
- 顶部信息条在 320 下按钮换行到下一行，不挤压正文。
- 页脚保留 `env(safe-area-inset-bottom)`；占位块不贴底。

| `phone.noSms` | 发布 | 平台不发送短信验证码，也不校验号码归属；请确认号码可用，联系前先核对对方身份。 | |
| `limit.title` | 限制 | 使用说明与已知限制 | |
| `limit.phone` | 限制 | 手机号自行填写，请自行核实 | 正文见 §19.1 |
| `limit.noAutoClose` | 限制 | 不会自动下架 | 正文见 §19.1 |
| `limit.session` | 限制 | 内存 session，重启失效 | 正文见 §19.1 |

### 18.3 数字、时间、号码

- **置信度**：整数百分比，`92%`；只展示服务端 `scorePercent`，前端不二次四舍五入后再判档。档位用 `tier`，不用百分比反推。
- **条数**：阿拉伯数字 + `条可能相关`；0 条时写“暂未发现可能相关的启事”，不写“0 条可能相关”（避免像计数器的噪音）。
- **时间**：列表与通知用相对时间（刚刚 / N 分钟前 / N 小时前 / 昨天 HH:mm / 10 月 21 日）；详情与表单用绝对时间 `2026-10-20 15:00`；`<time datetime>` 带机器可读值。
- **手机号**：输入存 11 位数字（`13800001234`）；展示格式化为 `138 0000 1234`；`font-variant-numeric: tabular-nums`；不做自动拨打按钮（避免误触），也不把号码拼进 `alt`/`title`。
- **pair 编号**：`#13 ↔ #27`，两端记录 ID；不是 pair ID，不要求用户理解内部主键。
- **示例数据**：稿面中的手机号一律 `138/139 0000 …` 虚构号段；真实用户数据不得进入稿面、注释或截图。

### 18.4 文案的五个反例（写法，不是词）

1. 把“操作失败”写成“系统异常，请联系管理员”——用户不知道能做什么。
2. 把“对方尚未公开”写成“无权限查看”——把正常等待说成越权。
3. 把“已降级”写成“AI 分析失败”——结果其实还在，只是引擎降级。
4. 把“分析中”写成“加载中”——分析是后台任务，离开页面不会中断，和页面加载不是一回事。
5. 把“关闭启事”写成“删除”——关闭不删除数据，也不自动恢复。

## 19. 已知限制与发布表单提示

### 19.1 已知限制区块（三条，缺一不可）

区块标题：`使用说明与已知限制`；位置：`/my` 底部（完整三条）+ 发布表单（第 1、2 条就地提示）。**不折叠**在 `/my`，因为这三条会直接影响用户对号码、下架与会话的判断。

| # | 标题 | 正文（逐字） |
|---|---|---|
| 1 | 手机号自行填写，请自行核实 | 平台不发送短信验证码，也不保证号码真实有效；联系前请先核对对方身份与物品特征。 |
| 2 | 不会自动下架 | 启事不会因为时间过去、匹配成功或被联系而自动关闭；只能由发布者本人手动关闭，系统不自动置位。 |
| 3 | 内存 session，重启失效 | 登录状态保存在服务端内存中，服务重启后需要重新登录；已发布的启事与配对数据不受影响。 |

- 三条都用编号方块（1/2/3）+ 粗体标题 + 说明，不用图标；编号是形状通道，色盲也能读。
- 第 1 条与发布表单的手机号提示必须同义：表单里是短句 `自行填写，请自行核实`，区块里是完整解释。
- 第 3 条只描述会话，不承诺“永不下线”；不说“重启后数据丢失”（数据不丢，丢的是登录态）。

### 19.2 发布表单：手机号与“自行填写，请自行核实”

```
手机号 *                                          11/11
[ 13800001234                                        ]
┃ 自行填写，请自行核实
┃ 平台不发送短信验证码，也不校验号码归属；请确认号码可用，
┃ 联系前先核对对方身份。
只做格式校验：11 位数字，以 1 开头。不会向你或对方发送任何短信。
```

- 提示**紧邻输入框**，在输入框下方第一行；用左侧 3px 警告色竖线 + 浅黄底，`<b>自行填写，请自行核实</b>` 加粗。不放进 tooltip、不折叠、不放到页面底部。
- 校验：11 位数字、以 `1` 开头；错误 `请输入 11 位手机号（示例：138 0000 0000）`。**不校验号段真实性、不发短信、不查归属地**。
- 号码只挂在启事上，`t_user` 不存手机号；UI 不提供“保存为我的手机号/下次自动填入”。
- “其他联系方式（选填）”保留 QQ/微信入口（≤64 字）；填了手机号时它只是补充，不替代手机号。
- 发布后默认不公开；可见规则就地说明：`默认不公开；在 75%–89% 的配对里由你主动公开，≥90% 的配对双方直接可见。低于 75% 不展示详情。`

### 19.3 不自动下架与手动关闭

- 没有定时任务、没有“匹配成功即关闭”、没有“被联系即关闭”；`t_record.status` 只由发布者本人改。
- 关闭入口在 `/my` 每条记录与详情页；确认框见 §13.5。
- 关闭后已有配对仍可查看；是否允许重新打开由 `allowedStatuses` 决定，UI 不自行推导。
- 不在 UI 写“到期自动下架”“系统会自动清理”之类承诺。

### 19.4 会话

- 登录态在服务端内存 session 中；服务重启后失效。页面在 401 时统一跳登录并提示 `登录已过期，请重新登录。`
- UI 不把“记住我”做成默认；不把 token 写进 `localStorage`（B2 决定存储方式，A3 只要求“刷新/重启后的行为可解释”）。
- 这条限制在 `/my` 的已知限制区块完整出现；登录页不重复，避免登录页承载过多说明。

### 19.5 不承诺的事

- 不承诺“号码真实”“对方就是失主”“高置信度一定正确”；高置信度只代表描述相似。
- 不承诺“匹配成功后自动联系/自动关闭”。
- 不承诺“通知永久保留”；保留策略未定，UI 不显示具体天数。
- 不承诺“深色模式”；v2 沿用 v1 的浅色 `color-scheme: light`。

### 20.2 视觉：不新增一套颜色

- 档位色复用现有语义 token：高 = `--color-success` / `--color-success-soft`；中 = `--color-warning` / `--color-warning-soft`；低 = `--color-text-muted` / `--color-surface-muted`。
- 如果实现时觉得语义不够，只能在 `tokens.css` 增加别名（`--color-tier-high` 等），**值必须引用现有 token**；组件里仍然不出现十六进制。
- 新增形状：`TierRail` 的三等分轨、`PairCard` 左侧 3px 档位条、`ContactStrip` 的虚线/实线两态、`MaskedBlock` 的虚线占位。它们都只用现有圆角/间距/描边 token。
- 反例：给高档加绿色渐变、给中档加“锁”图标、给低档加灰色蒙层。档位靠**文字 + 色点 + 底色**表达，不靠装饰。

### 20.3 响应式

| 断点 | 登录 | `/my` | 通知 | 配对卡片 | 遮蔽 |
|---|---|---|---|---|---|
| 320 | 卡片满宽、按钮满宽 | 单列；匹配摘要堆到下方 | 时间移到标题下方 | 两端上下堆叠，连接符隐藏 | 内联占位可换行；块级满宽 |
| 390 | 同上 | 同上 | 同上 | 同上 | 同上 |
| 768 | 卡片 400 宽 | 记录行单列（<900） | 时间回右侧 | 两端左右并排（≥860 更稳） | 块级宽度受 content-max 限制 |
| 1120 | 卡片居中 | 两列，右列 268px | 列表 max 760 居中 | 卡片不超过 760 阅读宽 | 描述块 760 |

- 断点只用 v1 的 768 / 1120；配对卡片的两端切换用 860（内容决定的局部断点），写在组件内，不改全局 token。
- 320 自检项：`document.documentElement.scrollWidth <= innerWidth`；长学号、长标题、长地点、长号码都不撑破；按钮换行不重叠。
- 不用 `100vh` 做全屏居中；用 `100dvh` + `padding-block`，避免移动端地址栏收起时跳变。

### 20.4 动效

- 只动 `transform` / `opacity` + 颜色/边框/阴影；开关滑块用 `transform: translateX()`；卡片 hover 只改边框/底色，不位移。
- 骨架 sheen 沿用 v1；`prefers-reduced-motion` 下关闭 sheen、开关滑块无过渡、通知行不做进入动画。
- 不做“数字从 0 涨到 92%”的计数动画：置信度是结论，不是游戏分数；滚动数字还会制造无意义的布局更新。
- 不做“通知滑入”动画：列表刷新时滑入会让用户以为有新通知，且增加 CLS 风险。

### 20.5 性能：设计阶段的约束与待测项

**这一节没有 v2 实测数字**，因为 v2 还没实现。以下是给 E2/D2 的硬约束，以及实现后必须测的项：

- **不引新运行时依赖**：不加 UI 库、图标库、图表库、日期库；v2 页面都是表单/列表/卡片，现有 Vue + CSS 足够。
- **路由级懒加载**：`/login`、`/my`、`/notifications` 各自独立 chunk；登录页不应把 `/my` 的列表组件打进首屏。
- **不引 Web 字体、不加大图**：登录页与列表页的 LCP 仍是文字；没有字体切换 CLS。
- **骨架与真实内容同构**：`/my` 行、通知行、配对卡的骨架尺寸与真实内容一致；任何异步提示条（降级、未读）都不能把内容顶下去。
- **列表分页**：`/my` 与 `/notifications` 复用 `PaginationBar`，不一次性渲染无限列表；条数多时不做“全量 DOM + CSS 隐藏”。
- **不传隐藏数据**：低档/未授权字段服务端不返回，既省带宽也避免“查看源码能看到”的安全问题。
- **预算（待实测核对，不是已测值）**：新增路由的懒加载 chunk 各自尽量 ≤ 10 kB gzip；列表首屏（v1）不因 v2 增加超过 10 kB gzip。若超出，优先拆共享组件与去掉未用样式，而不是压字体的可读性。
- **实现后测什么**：`/login`、`/my`、`/notifications`、详情页三档卡片各测 320/390/1280 的 LCP、CLS、横向溢出、控制台错误；INP 至少测“输入附言 200 字”“切换未读/全部”“开关授权”三条交互。测法沿用 §5.1，结果写进交付评论。

### 20.6 版式与密度

- `/my` 与通知是“扫读”页面：标题 16/600、正文 14、元信息 12；行高 1.4–1.6；一屏不要塞超过 5 条记录。
- 配对卡片信息密度高，但只允许一个视觉焦点：档位徽标 + 置信度；两端摘要用同字号，不靠字号分主次。
- 授权区是“表单中的表单”，用 1px 边框 + 8/12 内距收住，不用第二层阴影。

## 21. 无障碍

### 21.1 键盘路径

| 页面 | Tab 顺序 |
|---|---|
| 登录 | 品牌链接 → 学号 → 密码 → 显示密码 → 登录 → 返回列表 / 忘记密码 |
| 我的启事 | 跳转链接 → 品牌 → 导航 → 发布启事 → tabs → 每条记录的“查看详情/关闭启事” → 匹配摘要里的“查看可能相关/重试分析” → 分页 |
| 通知 | 跳转链接 → 品牌 → 导航 → tabs → 全部标为已读 → 每条通知（整行链接）→ 分页 |
| 配对卡片 | 查看对方启事 → 公开/撤回 → 标记已联系 → 忽略 → 下一条卡片 |
| 授权表单 | 开关 → 附言 textarea → 保存 → 取消；撤回确认框打开后焦点在“取消”，`Esc` 关闭并回到“撤回公开” |

- 所有可交互元素有 `:focus-visible` 环（v1 全局规则，2px + 2px offset）；不用 `outline: none`。
- 禁用动作保留可见理由，并用 `aria-disabled` 让键盘仍可聚焦读取理由（见 §15.7）。
- 原生 `<dialog>` 负责焦点陷阱；不自写弹层、不自写焦点循环。

### 21.2 读屏

- 标题层级：登录 `h1 登录`；`/my` `h1 我的启事` → 记录 `h2`；通知 `h1 通知`；详情保持 v1 的 `h1 启事详情` → 记录 `h2` → 匹配区 `h2` → 卡片标题 `h3`。
- 状态不靠颜色：档位徽标是“文字 + 色点 + 底色”；分析状态是“文字 + 形状（转圈/实心点）”；未读是“红点 + 加粗 + 浅底 + aria-label 未读”。
- 数字合并：`aria-label="3 条可能相关"`，视觉大数字 `aria-hidden`；置信度 `aria-label="置信度 92%"`，不让读屏读成“九十二百分号”。
- 遮蔽：占位块有完整句子，不读星号；真实值不在 DOM。
- 开关：`role="switch"` + `aria-checked` + 文字状态；附言错误 `aria-invalid` + `aria-describedby`。
- 通知时间：`<time datetime>` + 完整绝对时间在 `title`/`aria-label` 里；相对时间不单独成为唯一信息。

### 21.3 对比度（复用 v1 实测 token）

| 配对 | 值 | 结论 |
|---|---|---|
| 正文 / 白面板 | 16.17:1 | AA |
| 次要 / 白面板 | 5.93:1 | AA |
| 高置信度文字 / success-soft | 4.88:1 | AA |
| 可授权文字 / warning-soft | 5.76:1 | AA |
| 低档文字 / surface-muted | 5.24:1 | AA |
| 主按钮白字 / primary | 6.70:1 | AA |
| 控件描边 / 白面板 | 3.06:1 | SC 1.4.11 |

- 档位、未读、错误都不只用颜色：文字 + 形状（点/转圈/编号）+ 底色。
- 新增组件不引入新色值；若引入别名，必须重新跑对比度，不能“看起来够深”。

### 21.4 动效与认知

- `prefers-reduced-motion` 下关闭骨架 sheen、开关过渡、卡片 hover 过渡。
- 不自动播放、不闪烁；错误提示不用抖动动画。
- 一屏只有一个主任务：登录页只登录；`/my` 只管理自己的启事；通知只读与标已读；详情页的授权是卡片内的次级任务。

### 21.5 还没做 / 没测

- **没有跑 axe 或任何自动化审计**（不引新依赖）；上面是设计核对，不是审计分数。
- **没有真机/读屏实测**（NVDA / VoiceOver / TalkBack 都没跑）；E2/D2 实现后至少用一台 Android + 一个桌面读屏走一遍登录、授权、撤回。
- **没有 768 / 1120 的截图**；这两档的规则是设计约束，靠实现后的响应式断言验证。
- 深色模式未做；对比度表只对浅色成立。
