# 5.1 回归清单（ZHYYKFX-10）

用途：任何任务改动前后，按改动面勾选最小必要复测项。全部项都可以一条命令跑完：

```bash
node qa/run-all.mjs        # 接口 + 匹配评估 + E2E + 落库取证 + 跨页一致性，前后各重置一次库
```

判绿标准：
1. 除 `API-C-08`（DEF-01）与 `E2E-L-04`（DEF-02）两条**已登记缺陷**外，没有新的 `FAIL`；
2. 新增失败必须是新缺陷，不允许把已知缺陷从清单里删掉来「变绿」；
3. `db-evidence.txt` 末尾「结论：通过」；
4. 结束时库回到 seed 状态（脚本自动重置）。

## 1. 按改动面勾选

- [ ] `API-L-01..12` 列表：默认参数、字段白名单、筛选、分页、排序、参数非法
- [ ] `API-D-01..06` 详情：全字段、`allowedStatuses`、逻辑删除 404、非数字 id
- [ ] `API-C-01..13` 提交：边界长度、未来时间容差、contact 字符集、emoji、重复提交
- [ ] `API-U-01..05` 修改：全量语义、CLOSED 20003、缺字段 10001
- [ ] `API-S-01..05` 状态流转：全链路、终态 20002、同状态 20002

### 1.3 前端 · 列表页 / 筛选 / 分页

## 2. 触发时机

| 时机 | 跑什么 | 说明 |
|---|---|---|
| 本地改完一个模块 | 对应小节的用例（`node qa/api/run.mjs` 或单个 `node qa/e2e/*.mjs`） | 反馈快，不要求重置库 |
| 合并到集成分支前 | `node qa/run-all.mjs` 全量 | 必须，含重置与取证 |
| 合并 main 前 | 全量 + 人工确认两条缺陷状态 | 人类决定是否带缺陷合并 |
| 每日构建（若有） | 全量 + 保存 `qa/reports/run-all-output.txt` 作为趋势 | 关注「新 FAIL」与耗时变化 |

## 3. 红线（出现任意一条就不该合）

- [ ] 出现原因不明的 `FAIL`（不是 DEF-01 / DEF-02）
- [ ] `db-evidence` 有任何一项「不通过」
- [ ] 默认列表 total 不再是 21（说明 seed 或查询口径被改坏）
- [ ] `web/.env.local`、`application-local.yml` 被提交
- [ ] 为了让用例变绿而修改了 `docs/api-contract.md` 的既定契约（改契约要人类拍板）
- [ ] 新增了 Out of Scope 的能力（登录、图片上传、管理后台等）
