## 3. 一条命令复现

```bash
node qa/run-all.mjs
```

脚本做的事（前置：MySQL 已起、后端 18080、前端 5173 已起）：

1. 重置库到 `db/seed.sql` 初始状态；
2. 跑接口测试 → 匹配评估 → 前端 E2E → 落库取证 → 跨页一致性；
3. 再重置一次库（不让本轮 `E2E 走查记录` 和状态改动留在演示库里）；
4. 汇总各组退出码，完整输出写 `qa/reports/run-all-output.txt`。

单独跑某一组：`node qa/api/run.mjs`、`node qa/match/evaluate.mjs`、`node qa/e2e/walkthrough.mjs`、`node qa/db/evidence.mjs`、`node qa/e2e/consistency.mjs`。

## 7. 没测到 / 不在本期范围（明确写出来，避免「全绿」的误解）

| 项 | 原因 | 风险提示 |
|---|---|---|

| 安全渗透（注入 / 越权 / XSS） | 不属于 5.1；项目本身无权限体系 | 列表/详情/写接口对任何访客开放，属已声明的范围外风险 |
| 兼容性矩阵 | 只实测 Edge 155 | Firefox / Safari / 移动真机未验证 |
| 3.2 external 实现 | 人类口径：本期只认「本地实现 + 文档化替换路径」，external 另立任务 | 本期不评估 external 效果、不因未落地判 3.2 不通过 |
| 深色模式 | 人类拍板本期不做 | 已实测暗色偏好下仍为浅色，不算缺陷 |
| 图片/附件、登录、消息推送 | 父任务明确 Out of Scope | 无对应用例 |

| 浏览器返回/前进与深链接刷新 | 未单独覆盖（DEF-02 已暴露 URL 与状态不一致的一类风险） | 修复 DEF-02 后建议补一条前进/后退用例 |

## 8. 结论

- 接口层：契约范围内的 9 组接口在正常、边界、异常三类路径上行为一致；唯一不符合契约的是 DEF-01（输入校验漏到运行时）。
- 前端层：三页黄金路径全通，关键异常态（校验失败 / 后端不可用 / 空数据 / 404 / 500 / 匹配 503）都有确定的视觉与可恢复动作。
- 匹配：产品调用方式下 top1 10/10；不限类型时 top3 仍 10/10，主要差异是同事件的 LOST/FOUND 互为一对，说明分数口径可信、方向过滤是该带的。
- 建议：阶段 6 可开工；合并 main 前按 [回归清单](./5.1-regression-checklist.md) 复跑 `node qa/run-all.mjs`，DEF-01 修复后把 `API-C-08` 的 `knownDefect` 标记去掉即可转正。
