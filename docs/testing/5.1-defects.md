## DEF-01 · `occurredAt` 非法日历值导致 500，契约要求 10001

| 项 | 内容 |
|---|---|
| 严重级别 | **P2**（不影响正常提交路径，但违反错误码契约、在日志里制造 ERROR） |
| 对应任务 | ZHYYKFX-6（3.1 后端接口） |
| 用例 | `API-C-08`（`qa/api/run.mjs`，豁免标记 `knownDefect: DEF-01` 已于 REG-01 回归移除） |
| 状态 | **已修复**（ZHYYKFX-20 @`3548a27`）· 2026-10-22 回归 `API-C-08` **PASS** |

**现象**：`POST /api/records` 传 `occurredAt: "2026-13-40 25:61:61"` 返回 `HTTP 500 / code 10005`，响应体是「服务器内部错误」。

**复现**：

```bash
curl -s -i -X POST http://localhost:18080/api/records \
  -H 'Content-Type: application/json' \
  -d '{"type":"LOST","title":"测试标题","description":"测试描述内容","location":"测试地点","occurredAt":"2026-13-40 25:61:61"}'
```

**期望 vs 实际**：契约 §5.1 要求 `occurredAt` 格式严格，§5.3 规定校验失败回 `400 / 10001`（可带 `fieldErrors`）；
实际回 `500 / 10005`，并且后端日志打 `ERROR 未预期异常` + 完整堆栈。

**定位**（只读排查，未改代码）：

```
java.time.format.DateTimeParseException: Text '2026-13-40 25:61:61' could not be parsed:
    Invalid value for MonthOfYear (valid values 1 - 12): 13
  at java.time.LocalDateTime.parse(LocalDateTime.java:494)
  at com.findit.campus.record.web.dto.RecordCreateRequest.occurredAtAsDateTime(RecordCreateRequest.java:129)
  at com.findit.campus.record.service.RecordService.create(RecordService.java:105)
```

`@Pattern("\\d{4}-\\d{2}-\\d{2} \\d{2}:\\d{2}:\\d{2}")` 只校验形状，13 月/40 日/25 点都能过；真正的解析在 service 层，
`DateTimeParseException` 没有对应的异常出口，落到兜底 10005。

**影响范围**：所有带 `occurredAt` 的写接口（`POST /api/records`、`PUT /api/records/{id}` —— 两者复用同一个 DTO）。
前端提交页用 `datetime-local`，UI 上很难造出非法日历值，所以**不是演示阻塞项**；但任何脚本/第三方调用方会拿到 500，
且错误日志被污染（ERROR 级别会被当成真实故障排查）。

**修复方向（给 3.1，不由我改）**：`occurredAtAsDateTime()` 捕获 `DateTimeParseException` → 抛 `BizException(10001, fieldErrors=[{field:"occurredAt", reason:"发生时间不是合法日期"}])`；
或把 `@NotFutureMinutes` 与格式解析合并成一个自定义约束，在约束层统一产出 10001。
**实际修复**（ZHYYKFX-20 @`3548a27`）：新增 `StrictDateTime` / `StrictDateTimeValidator`，把日历合法性并进约束层统一产出 `10001`。
REG-01 回归：豁免标记已移除，`API-C-08` 四种非法格式均回 `400/10001`，**转绿**。

## DEF-02 · 重置筛选后 URL 残留参数，刷新/分享会让筛选「复活」

| 项 | 内容 |
|---|---|
| 严重级别 | **P2**（当次页面结果正确，但 URL 与状态不一致；分享链接会带上别人的筛选） |
| 对应任务 | ZHYYKFX-8（4.1 前端三页面；`useRouteQueryState` 属该任务交付） |
| 用例 | `E2E-L-04`（`qa/e2e/walkthrough.mjs`，豁免标记 `knownDefect: DEF-02` 已随修复移除） |
| 状态 | **已修复**（ZHYYKFX-21 @`1349f09`）· 2026-10-22 回归 `E2E-L-04` **PASS** |

**现象**：列表页输入关键词「钱包」→ 点「重置筛选」→ 列表恢复为 21 条，输入框也清空了，
但地址栏仍是 `/?keyword=%E9%92%B1%E5%8C%85`；此时刷新页面，筛选条件又回来了（回到 2 条）。

**复现步骤**：

1. 打开 `http://localhost:5173/`（21 条，10 张卡片）；
2. 在「关键词」输入 `钱包`，等列表变成 2 条，地址栏出现 `?keyword=钱包`；
3. 点「重置筛选」，列表变回 21 条、输入框清空，**但地址栏仍带 `?keyword=钱包`**；
4. 按 F5 刷新 —— 列表又变回 2 条。

**期望 vs 实际**：基线声明「URL 即状态」（`docs/ui-baseline.md` §1 / `frontend-baseline` §3.1）。
重置应该让 URL 与界面同源：期望地址栏回到 `/`，实际残留旧参数，导致刷新、收藏、分享三种场景都重现旧筛选。

**定位**：`web/src/composables/useRouteQueryState.ts` 写回 URL 时用
`router.push({ query: { ...route.query, ...prune(next, defaults) } })`：
`prune` 会把「等于默认值/空串」的键删掉，但 `...route.query` 里的旧键仍在，于是 `type=FOUND`、`keyword=钱包`
永远不会被移除。同一个 bug 还会让「先选类型、再重置、再改别的筛选」叠加出预期外的组合。

**影响范围**：列表页所有筛选 + 分页（`page` 越界后重置页码也会残留）。详情/提交页不受影响。

**修复方向（给 4.1/4.2）**：写回时不要 merge 旧 query，而是「只保留非默认值 + 需要透传的参数」重建 query，
例如 `router.push({ path: route.path, query: prune(next, defaults) })`；如果确实要保留外部参数，先把受控键从旧 query 里剔除。

## DEF-03 · 匹配区 503 文案重复

| 项 | 内容 |
|---|---|
| 严重级别 | **P3**（纯文案，无功能影响） |
| 对应任务 | ZHYYKFX-8（4.1；`MatchPanel` 的 `title` 与 `describeError()` 文案重叠） |
| 用例 | `E2E-E-06` 截图 `qa/reports/screenshots/18-detail-match-503.png` |
| 状态 | 未修复（建议随下次前端改动一起处理） |

**现象**：匹配接口返回 503/30002 时，匹配区提示条显示
「**匹配服务暂不可用** 匹配服务暂不可用，请稍后再试 requestId …」，同一句话出现两次。

**复现**：详情页把 `/api/match` 打回 503（`code:30002`），点「开始匹配」。脚本里用 Playwright `route.fulfill` 复现，
真实场景对应后端切到 external 且未配置 Key 时。

**期望 vs 实际**：期望「标题说类别、正文说动作」不重复，例如标题「匹配服务暂不可用」+ 正文「请稍后再试」。
实际标题与正文都是 `describeError(30002)` 的同一句。

**影响**：只影响观感与专业性，不影响降级行为（详情主体仍可用、重试可用）。

## 观察项（不是缺陷，但建议记录到 6.x）

| 编号 | 现象 | 说明 / 建议 |
|---|---|---|
| OBS-01 | `/api/match` 服务端耗时抖动：同一数据量（24 行）连续 8 次为 375/18/357/367/379/359/14/12 ms，而列表接口稳定 5–8ms | 本轮性能不在范围，只记录。演示够用，但「有时 0.4 秒」会被感知；建议单独立一条性能排查任务（先看快照写入与连接池，不要先怀疑算法 —— `tookMs` 显示引擎本身 0–1ms） |
| OBS-02 | 详情页「最后更新」显示的是 seed 导入时间（如 `2026-10-22 15:00:10`），不是记录的 `created_at` | `db/seed.sql` 插入时只写 `created_at`，`updated_at` 走 `DEFAULT CURRENT_TIMESTAMP`。属数据脚本观感问题，建议 seed 显式写 `updated_at = created_at`，避免演示时被问「为什么刚导入就更新过」 |
| OBS-03 | 前端没有 `data-testid`，E2E 只能靠类名/文案定位 | 改文案或类名会让用例失败（维护成本，不是产品回归）。建议三页关键节点补 testid，见 [走查文档 §5](./5.1-e2e-walkthrough.md) |
| OBS-04 | 请求体不是合法 JSON 时，`10001` 的 `fieldErrors` 是空数组 | 契约未规定此场景，前端也只 toast 不落字段，行为可接受；若后续要做「精确提示」，在 `HttpMessageNotReadableException` 出口补一条通用 reason |
