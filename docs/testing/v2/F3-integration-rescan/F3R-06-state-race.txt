## ④ 真并发（InnoDB 行锁编排，把交错钉在指定位次上）

编排：A 会话持该行 X 锁 3s（FOR UPDATE + DO SLEEP，不改任何列）
      → C 会话在 A 之后入队，把 status 改成 CLOSED 并提交（排队等锁）
      → HTTP PUT 最后入队：它的快照读早已读到 PENDING（A 从未改 status），
        所以预检查通过、必定走到 updateContent，然后被锁挡住，等 C 提交 CLOSED 之后才执行。
      此时若返回 20003 且正文未变，就是「预检查与 UPDATE 之间的窗口被条件更新关闭」的直接证据，而不是串行巧合。

PASS  R1 锁编排：PUT 应因条件更新返回 409/20003，正文零写入，且 PUT 确实被行锁阻塞过
