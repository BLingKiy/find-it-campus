# 选题：问题不在「没有平台」，在「信息不聚合」
- 现状三条渠道：微信群、表白墙、宿舍楼下纸质启事
  - 失主在群里刷屏询问，招领信息却在另一个群
  - 纸片启事只在原地可见，跨校区无效
  - 即使两边都发了，也没有任何机制把「丢了黑钱包」和「捡到黑钱包」连起来
- 结果：最该发生的匹配，靠运气
- v1 把这条链路做成可运行的系统：发布 → 检索 → 按描述语义找匹配 → 走完状态流转
- v2 补上链路后半段：**配对打分 → 通知到人 → 分档放行联系方式 → 双方确认或忽略**

> 我们做的不是「再一个信息发布页」，是「让两条本来碰不上的启事发生关系，并且把关系走完」。

# 选题难度：难在三组约束必须同时成立
- **数据约束**：七张表承担复合职责 —— `t_record` 一表两用（寻物/招领，另带 `pair_state` 四值）、`t_pair_score` 一行就是一对且唯一键 `(lost_id, found_id)`、`t_match_result` 既是评估证据又能反查候选
- **隐私约束**：同一份数据要同时满足「匿名也能读、写了要留名、号码只给够格的人」——三条互相拉扯，靠**输出层遮蔽 + 分档放行**而不是靠多张表化解
- **可替换约束**：评分看的不是「用了 AI」，是「能不能把 AI 换掉而调用方不动」，同时**降级必须留下原因**而不是静默顶替

> 难度不是技术栈堆得多，是「约束交叉时还能跑通，并且每一条都能在源码里指出行号」。

# 部署：单端口 8088，四条命令启停
- 交付物是一个 zip：jar + `web/dist` + Nginx 1.30.6 + `db/` + 四个 PowerShell 脚本；解压即用，**不需要管理员、不注册服务**
- `install.ps1`（建库 utf8mb4 + 导种子 + 生成配置）→ `start.ps1` → `status.ps1` → `stop.ps1`
- `start.ps1` 先等后端 `/api/health` 三项全绿（`code=0` / `status=UP` / `db=UP`）才起 Nginx；任一步失败回滚本次启动的进程
- v2 新增的东西对部署是透明的：会话用 `JSESSIONID` Cookie，经 Nginx 反代仍是同源，不需要额外 CORS 或 sticky 配置
- 边界照实说：无 HTTPS、开机不自启、**会话存在进程内存里，重启即失效**（用户表现为下一次请求 401，需重新登录）

# 数据模型：7 张表 · 82 列 · 9 条外键 · 23 个 CHECK
- `t_user` 7 列：**没有手机号列**；`student_no` 唯一、口令是 bcrypt(cost=10) 摘要
- `t_record` 17 列：`status` 只有 `PENDING` / `COMPLETED` / `CLOSED` 三态（v1 的 `CLAIMED` 已从枚举与 DDL 删除），另带 `pair_state` 四值（`PENDING`/`SCORING`/`READY`/`DEGRADED`）
- `t_pair_score` 21 列：一行 = 一对 LOST↔FOUND，唯一键 `(lost_id, found_id)`，`score` 是 `DECIMAL(5,4)`，四态 `NEW`/`CONTACTED`/`MATCHED`/`IGNORED`，两个 `*_confirmed_at` **同时非空 ⇔ MATCHED**（库层 CHECK 兜住）
- `t_notification` 8 列：`PAIR_MATCH` / `PAIR_UNLOCK` / `SYSTEM`，唯一键 `(user_id, pair_id, type)` 天然去重；标题与正文**写入前已打码**
- `t_access_log` 11 列：只插不改不删，**没有号码列也没有附言列**——审计只回答「谁在何时看了哪对、结果如何」
- `t_category` / `t_match_result` 沿用 v1（后者不参与业务读写路径，只作评估证据）

> 七个上下文各写各的表，没有两处写同一张表；23 个 CHECK 把「靠约定维持的不变量」变成「靠数据库维持的不变量」。
<!-- note: 90 秒。这是 v2 最难的一页，只讲三句：一对外键双向 + 唯一键 → 不会出现"同一条 LOST 被两个人重复配对"；CHECK 把两个确认时间绑成一对状态；审计表刻意没有号码列。 -->

# 权限矩阵：17 × 3 = 51 格，每格都有状态码
| 接口 | 匿名 | 登录非所有者 | 所有者 |
|---|---|---|---|
| `GET /api/records` | 200（只给 `PENDING`，逐条遮蔽，无号码无称呼无正文） | 200（同一集合，`isMine=false`） | 200（本人的 `PENDING` 明文；本人的终态记录**同样不在公共列表**） |
| `GET /api/records/{id}` | 200（遮蔽）；`COMPLETED`/`CLOSED` → 404 | `PENDING` 200（遮蔽）；`COMPLETED` 且**合格对端** 200（遮蔽）；其余 404 | `PENDING` 200（明文 + pair 卡片）；`COMPLETED`/`CLOSED` **本人也 404** |
| `POST /api/records` | 401 / 10006 | 200（`publisherId` 取 session） | 200 |
| `PUT` / `PATCH status` / `DELETE` | 401 | 403 / 10007（不可见状态则 404） | 200（`PENDING`）；终态 → 409 |
| `POST /api/match` | 401 | 200（候选遮蔽；`COMPLETED` 召回但标 `detailAccess=RESTRICTED`） | 200（同左） |
| `PATCH /api/pairs/{id}`、取号、授权 | 401 | 403（非参与方） | 200 / 403（`50002` 档位不足、`50005` 配对失效）/ 409（`50003` 终态）/ 404（`20004`） |
| `GET /api/notifications`、`PATCH .../read` | 401 | 200（只给自己）；改别人的 → 403 | 200 |

- 门禁在 `AuthGateFilter`，**早于 `DispatcherServlet`**：规则是「非 GET/HEAD 的 `/api/**` 一律要登录」，例外只有 `login` / `logout` / `ops/pair-scan` 三条 —— fail-closed，「该拦但还没实现」的路径匿名访问也是 401 而不是 404
- 不可见一律 404、不返回 403：不区分「不存在」与「不够格」，避免泄露终态记录是否存在
- 「合格对端」是登录非所有者的子集（有可用 pair 且 `score ≥ 0.90`），不是第四种身份
<!-- note: 90 秒。这是「有没有权限模型」的正面回答：有，7 行 × 3 格写在设计文档 §5.3，每格带状态码。指一下最后两条——401 而不是 404、404 而不是 403，这两个选择都是防信息泄露。 -->

# 新增能力一：登录 —— 身份只认服务端会话
- 凭证只有两样：`studentNo` + `password`；口令用 bcrypt(cost=10) 校验，**库里存摘要不存明文**
- 会话是 `HttpSession` + `JSESSIONID`：`HttpOnly`、`SameSite=Lax`、30 分钟无活动失效、`tracking-modes: cookie`（不生成 URL 重写会话）
- **三种失败对外完全同形**：账号不存在、账号停用、密码错误 → 同一个 401 + 同一句「学号或密码不正确」，防账号枚举
- 身份不来自请求体：`publisherId` 从会话取，客户端传什么 `userId` / `publisherId` 都不作数
- 前端配套：`/login` + 路由守卫（未登录访问私有页跳登录并带 `redirect` 回跳）、401 只提示一次不刷屏、顶栏显示本人学号
- 已知代价：会话在进程内存里，**重启即失效**（第 7 页与第 24 页各说一次）
<!-- note: 90 秒。指着图走一遍：浏览器 → /api/auth/login →  bcrypt 校验 → 建会话 → Set-Cookie；下面那条 401 分支是被拦的写请求。评委最常问的"身份能不能伪造"，答案是第三、四条。 -->

# 隐私底座：遮蔽只写在一处，五个出口共用
- 出口清单：列表、详情、`/api/match`、`/my`（含 pair 卡片）、通知——**都调同一个 `MaskingPolicy`**，前端不得自行「还原」
- 描述/标题打码按固定顺序跑四条正则：18 位证件号 → 11 位手机号 → 带 QQ 关键词的 5–9 位号 → 「昨天 14:30」类相对时间；顺序不可换（先手机号会把长数字串切成两段）
- 地点：先按**码点**截 8 个，再去掉末尾的精确定位片段（`A12座`/`3 号楼 201`），兜底返回「校园内」——实测 `图书馆三楼自习区A12座` → `图书馆三楼自习区…`
- 联系人称呼：空 → 「匿名同学」；否则只留首字 + `**`
- 裸 5–9 位数字**不打码**（学号、卡号、房间号是正常内容），绝对时间 `2026-10-21 13:30` 也不打
- 取证方式不是看代码而是 grep：五个出口逐个拉响应（`docs/testing/v2/C1-masking-evidence.md` + 结果文件）、全局 28 个探针扫描匿名/非本人响应体与通知标题正文（`F2-phone-scan.txt`，**0 命中**）、前端 DOM 扫描（`C2-frontend-masking/dom-scan.txt`）
<!-- note: 90 秒。为什么必须单点：列表和详情各写一份，就会出现"列表打码了、详情忘了"的漏口，而这种漏口在功能测试里完全看不出来，只有拿手机号 grep 才能发现。 -->

# 新增能力二：三档 —— 联系方式什么时候给
| 档位 | 判定（分数 `score`） | 对方视角 | 本视角 | 配置键 |
|---|---|---|---|---|
| **直看 `DIRECT`** | `score ≥ 0.90` | 可直接取号 | 按钮可点，`contactAvailable=true` | `findit.pair.contact_direct_threshold` |
| **可授权 `AUTHORIZABLE`** | `0.75 ≤ score < 0.90` | **仅当对方已授权**才可取号 | 取号返回 200 + `available=false`（不是 403） | `findit.pair.contact_unlock_threshold` |
| **低置信 `LOW`** | `score < 0.75` | 拒绝 | `GET .../contact` → 403 / **50002** | 同上（下界） |

- 阈值关系被启动校验钉死：`unlock < direct`、`notify ≥ unlock`，配错**直接启动失败**并指出该改哪个键
- 分数比较用 `BigDecimal.compareTo` 而不是 `equals`：`0.90` 与 `0.9000` 在 scale 上不等、在数值上等
- 授权是**逐端**的：`POST /api/pairs/{id}/contact-unlock` 带 `PUBLISH` / `REVOKE`，各端只改自己那一列（`lost_unlocked_at` / `found_unlocked_at`），撤回随时可作
- 「够格才让授权」：`score < 0.75` 时连 `PUBLISH` 都拒绝（50002），避免低质量配对被拉去交换号码
- **`PairCard` 里没有 `contact` 字段，任何身份都没有**——号码只有一个出口 `GET /api/pairs/{id}/contact`，这条由 SQL 白名单测试固定

> 三档不是三个按钮，是三个可核对的判据：一个阈值配置 + 一句 `compareTo` + 一个唯一出口。
<!-- note: 120 秒。这是 v2 的核心页。先念三档的分数边界，再讲两条容易忽略的：available=false 是 200 不是 403（是正常业务状态，前端要渲染成提示）；卡片永远不含号码，所以"泄露"只能发生在唯一一个出口上，审计也就只需要盯那一个出口。 -->

# 配对打分链路：异步、幂等、可降级
- 触发：`t_record` 内容变化后由 `@TransactionalEventListener(AFTER_COMMIT)` + `@Async` 投递，**事务回滚就不会发**；线程池 2 worker + 队列 200，满了**丢弃并计数**（不无限堆积内存）
- 并发：一对 LOST↔FOUND 用 MySQL 命名锁 `GET_LOCK('pair:{lost}|{found}', 5)` 串行化，两个入口（事件与兜底扫描）撞在一起也只有一条在写
- 幂等：两边文本各算一次 SHA-256，**内容没变就整对跳过**；变了的只更新 `score`/`engine`/`latency_ms`/`tokens`/两个 hash 列——9 列白名单，**绝不把用户 `IGNORED` 的状态翻回 `NEW`**
- 降级：DeepSeek 不可用时用本地关键词打分，并在 `degraded_reason` 写下原因；`/api/match` 反过来**刻意不降级**
- 兜底：每天 03:30 一次全量扫描 + 运维手动触发（`X-Ops-Token`），单飞冲突返回 409 / 50006

> 「异步 + 兜底扫描」是同一件事的两半：前者保证及时，后者保证不漏；两边共用同一套幂等判定，所以重复触发是安全的。
<!-- note: 90 秒。重点讲第三句的白名单：重算分数不能顺手把用户的手动决定改掉，这是任务书冻结的口径，落在 SQL 的列清单上——不写清列清单，将来谁都可能多加一个 SET。 -->

# AI 亮点一：三条边界把「接口独立」做实
| 边界规则 | 具体约束 | 挡住的变化 |
|---|---|---|
| **引擎不碰数据库** | 不注入 Mapper、不写库，只消费调用方递进来的候选池与两端文本 | 换实现不必理解表结构；外部实现可单测覆盖，不用起库 |
| **引擎只返回 `recordId + score + reason`**（pair 侧只返回 `score + reason + 引擎标识`） | 展示字段由 service 回表补齐，可见性规则只存在一处 | 不会出现「每个算法各实现一遍谁能看什么」 |
| **引擎不知道 HTTP** | 没有 `HttpStatus`、不接收 DTO，异常只有 `MatchEngineException` / `PairScoreException` | 引擎可被任何入口复用，不背 HTTP 概念 |

- 切换方式是**一个配置值**：`findit.match.engine=local|external`，容器里恒只有一个 `MatchEngine` bean
- `KeywordEngineSwappabilityTest` 在**同一调用点**注入 Fake 实现与真实实现，断言两者都满足契约（≤ `topN`、≥ `minScore`、去重、降序、`score ∈ [0,1]`）
- 换实现的改动面：新增一个 `@Bean` 与一个配置值；`MatchService` / `MatchController` / 请求响应 DTO / 前端**全部不动**

> 「接口独立」不是画在图上的一句话，是这三条约束，且每一条都能在源码里指到对应位置。
<!-- note: 90 秒。这一页是技术先进性 20 分的一半。要说透「候选池为什么由调用方给」：如果引擎自己查库，换实现就得把三档可见性规则再实现一遍。 -->

# AI 亮点二：降级有原因，熔断有阈值，且两个出口语义不同
- **pair 链路会降级**，七个原因写进 `degraded_reason`：`EMPTY_KEY`、`UNAUTHORIZED`、`TIMEOUT`、`NON_JSON`、`SCORE_OUT_OF_RANGE`、`HTTP_ERROR`、`CIRCUIT_OPEN`
  - `EMPTY_KEY` 与其余六个的区别要记住：空 Key 是「没配」，根本没发生网络调用；后六个是「配了但不通」——运维处置动作完全不同
- **熔断**：连续 5 次失败开闸 5 分钟（`circuit-failure-threshold: 5` / `circuit-open-duration: 5m`），期间直接用本地关键词，不再打外部
- **`/api/match` 刻意不降级**：引擎不可用就是 503 / `30002`，不用关键词分数顶替 —— 匹配快照 `t_match_result` 会被当成语义结果引用，顶替等于污染评估数据
- 降级留痕可核对：`t_pair_score.engine` 记 `LOCAL_KEYWORD`、`latency_ms` 与 `tokens` 置空，`t_record.pair_state` 落 `DEGRADED`，前端详情出现「已按本地关键词估算」横幅
- 证据：`docs/testing/v2/D1-deepseek-live.md`（真调，只记 model / `latency_ms` / tokens）与 `D1-degradation.md`、`qa/e2e/f2-degradation.mjs`（拔 Key 走通黄金路径）

> 密钥纪律：`application.yml` 里**没有** api-key 这个键，只从环境变量 `DEEPSEEK_API_KEY` 读——配置里出现密钥字段，就是给「把 key 提交进仓库」开门缝。

# 已知限制（四条硬口径 + 实现边界，逐条说明代价）
- **手机号不做短信验证**：只校验 `^1[3-9]\d{9}$` 格式，`t_user` 里没有手机号列。**号码真实性由当事人自行核实**——平台只负责把它交到够格的人手里
- **不自动下架**：`COMPLETED` / `CLOSED` 只能本人手动标记；到期只是「公共列表不再返回」，**读时窗口**判定，不改写 `status`，也不新增调度器。代价：本人看不到自己的完成记录在公共列表已消失，要看「我的启事」
- **会话存进程内存**：重启即失效，用户表现为下一次请求 401 需重新登录。代价换的是零额外依赖（不引 Redis、不引持久化会话存储），前提是**单实例部署**
- **pair 链路可降级，`/api/match` 不降级**：前者降级留 `degraded_reason`、后者直接 503 / `30002`。这是**刻意的不对称**，不是遗漏——匹配快照会被当成语义结论引用
