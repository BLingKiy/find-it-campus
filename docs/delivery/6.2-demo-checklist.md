# 6.2 演示前准备与自检清单

> 这份清单只回答一件事：**答辩/录屏当天，怎么在 15 分钟内把环境恢复到「可演示」状态，并证明它是可演示的。**
> 自检不是「看一眼觉得没问题」，是一个会返回退出码的脚本：`node docs/delivery/tools/demo-path-check.mjs`。

## 2 三分钟把环境拉起来

按顺序执行，每一步都有「成功的样子」。

### 2.1 起数据库并重置到 seed 初态

```bash
cd <仓库根>
mysql -u root < db/schema.sql                    # 建库建表（可重复执行，会清空数据）
mysql -u root find_it_campus < db/seed.sql       # 导入 9 个分类 + 24 条记录
```

本机（`mysql` 不在 PATH 时）：

```bash
C:/Project/tools/mysql/mysql-8.0.29-winx64/bin/mysql.exe -u root < db/schema.sql
C:/Project/tools/mysql/mysql-8.0.29-winx64/bin/mysql.exe -u root find_it_campus < db/seed.sql
```

**成功的样子**：

```bash
mysql -u root -N -e "SELECT COUNT(*) FROM find_it_campus.t_record; SELECT COUNT(*) FROM find_it_campus.t_category;"
# 24
# 9
```

> 这两个数字是后面所有讲解词的基础：24 条记录里有 21 条是「待认领」，所以列表页写「共 21 条」。
> 只要真实数字不是 24/9，讲解词里的所有数字都要作废，先重新导入。

### 2.2 起后端（18080）

```bash
cd server
export JAVA_HOME="C:/Project/tools/jdk17/jdk-17.0.20.1+1"    # Windows 无此路径时用系统 JDK 17
./mvnw spring-boot:run
```

**成功的样子**：日志末行 `Started FindItCampusApplication in X seconds`，并且

```bash
curl -s http://localhost:18080/api/health
# {"code":0,"message":"ok","data":{"status":"UP","db":"UP","version":"0.0.1-SNAPSHOT","engine":"local"},"requestId":"…"}
```

三个字段都要对：`db=UP`、`engine=local`（不是 `external`）、`status=UP`。

### 2.3 起前端（5173）

```bash
cd web
cp .env.example .env.local        # 已存在则跳过；该文件不进仓库
npm install                       # 首次或换机器时
npm run dev
```

**`.env.local` 必须包含这两行**（少了第二行，页面会用 mock 数据，看起来一切正常但请求根本没到后端 —— 这是 4.1 踩过的坑 P-04）：

```
VITE_API_BASE_URL=/api
VITE_USE_MOCK=false
```

**成功的样子**：浏览器打开 `http://localhost:5173/` 能看到 10 张卡片；或在终端验证代理：

```bash
curl -s "http://localhost:5173/api/records?page=1&pageSize=1" | head -c 120
# {"code":0,"message":"ok","data":{"page":1,"pageSize":1,"total":21,…
```

`total` 必须是 21。如果是 22 或更多，说明库没重置到 seed 初态。

## 3 一条命令做自检（录之前必须 10/10）

```bash
cd docs/delivery/tools
npm install          # 首次
node demo-path-check.mjs
```

它会用真实浏览器把 `6.2-recording-script.md` 里的 10 个步骤原样走一遍，逐条断言「入口存在 + 结果可见」，并把截图写到 `../assets/shots/`、结果写到 `../assets/demo-path-check.txt`。

**通过的样子**（最后一行必须是 `10/10`，退出码 0）：

| 段 | 断言 | 期望 |
|---|---|---|
| D-01 | 首页列表 | 10 张卡、共 21 条、3 页 |
| D-02 | 类型筛选招领 | URL `?type=FOUND`，10 个类型徽标全是「招领」 |
| D-03 | 关键词钱包 | 共 2 条 |
| D-04 | 详情 1 号 | 7 个字段 + 描述 + 2 个状态按钮 |
| D-05 | 点开始匹配 | 真发 `POST /api/match`，HTTP 200、`code=0`、top1 = 13 号、带百分比 |
| D-06 | 提交 | 跳 `/records/<id>?created=1`、提示「发布成功」 |
| D-07 | 回列表 | 首位是刚提交的、总数 22 |
| D-08 | 接口回读 | `GET /api/records/<id>` 返回同一条 |
| D-09 | 标记已认领 | 徽标变「已认领」，只剩「标记为已关闭」 |
| D-10 | 再搜钱包 | 共 1 条 |

**注意：这个脚本会改库**（提交一条、认领一条）。**自检通过后必须再重置一次库**，否则录屏时总数会是 22 而不是 21：

```bash
mysql -u root < db/schema.sql && mysql -u root find_it_campus < db/seed.sql
```

## 4 录前时间线

| 时点 | 动作 | 通过标准 |
|---|---|---|
| T-30 min | 重置库 → 起后端 → 起前端 | `/api/health` 返回 `db=UP`，首页 21 条 |
| T-20 min | 跑 `demo-path-check.mjs` | 10/10，退出码 0 |
| T-15 min | **再重置一次库** | 首页回到 21 条、1 号是「待认领」 |
| T-10 min | 浏览器准备：新窗口、1280×900、缩放 100%、隐藏书签栏、F12 打开并切到 Network（过滤 `match`、勾 Preserve log）、关掉所有通知 | 屏幕上只有浏览器 |
| T-5 min | 打开 `6.2-recording-script.md` §3「一页速查」贴在显示器边；PPT 打开在放映模式待切 | 不需要再切换文档 |
| T-2 min | 试录 15 秒，回放确认麦克风与画质 | 能听清、字不糊 |
| T-0 | 开录 | — |

## 5 失败预案

| 症状 | 最可能原因 | 现场处置 |
|---|---|---|
| 首页空白 / 一直骨架屏 | 后端没起，或 `VITE_USE_MOCK` 没设成 `false` | 先 `curl /api/health`；不通就重启后端。**不要临时改成 mock 硬录**，那会把「真接口」的证据拆掉 |
| 首页「共 22 条」或更多 | 库不是 seed 初态（自检或上一次录屏留下的数据） | 重置库 + 刷新页面。重录必做 |
| 匹配结果为空 | 记录被改过；或 1 号的分类被换成别的 | 重置库后重试。仍为空则查 `GET /api/records/13` 是否 `PENDING` |
| 匹配报 503 / `30002` | `FINDIT_MATCH_ENGINE` 被设成了 `external` | 去掉该环境变量或设为 `local` 重启后端 |
| 提交报 `40001/40002` | 分类字典没导入，或选的分类被停用 | 重置库；分类下拉应能看到 8 个启用的分类 |
| 端口被占用（18080 / 5173） | 上次的进程没退干净 | `netstat -ano \| findstr 18080` 找 PID，**只结束那个 PID**；不要按名字杀 `java`/`node`，可能误伤其他服务 |
| 页面中文变成方块 | 系统缺中文字体 | 换机器演示；本项目页面与 PPT 都依赖「微软雅黑」 |
| 录到一半后端挂了 | 连接池或机器休眠 | 停录，重启后端 + 重置库，从 S3 重录（前两段不用重来） |

**总原则**：宁可停下重录，也不要在视频里解释报错。视频里出现的每一个红字都要能当场说明白，否则剪掉。

## 6 答辩当天的额外自检

- [ ] 演示机与录制机的浏览器缩放一致（100%），否则截图与视频里的排版会不同
- [ ] 演示机没有开 VPN / 代理：前端走的是 Vite 代理，代理会把 `localhost` 请求也劫走
- [ ] 库里没有上一场演示留下的记录（`SELECT COUNT(*) FROM t_record` = 24）
- [ ] `t_match_result` 可以是空表（第一次匹配才会写入），不影响演示
- [ ] PPT 里答辩人与指导教师姓名已填（`6.2-defense-ppt.md` 封面还是 `〈姓名〉` 占位）
- [ ] 答辩前把 PPT 的每条「已完成」对一遍 `6.2-claims-evidence.md`，被问到时能直接翻到证据页
- [ ] 两条 P2 缺陷只答「已登记，修复任务 ZHYYKFX-20 / ZHYYKFX-21 进行中，回归复跑待完成」，不说「已修复」
- [ ] 视频文件已拷到答辩机本地，**不要依赖网络播放**
